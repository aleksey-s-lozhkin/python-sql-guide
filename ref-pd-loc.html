loc и iloc: имя против номера Выбор строк и колонок по подписи и по позиции: срезы, маски, запись и пять ошибок

loc ищет по подписи — как человека по фамилии в списке гостей. iloc ищет по позиции — как вагон по номеру в составе. Здесь собрано, что обычно ищут в документации: полная таблица выборок, включительная граница loc, безопасная запись и ловушки, из-за которых pandas молча возвращает не то.

Самое главное
  • loc выбирает по меткам индекса и именам колонок, iloc — по целочисленным позициям. При RangeIndex они совпадают, поэтому путаница долго остаётся незамеченной.
  • Срез loc включает правую границу ("anna":"olga" — три строки), срез iloc — нет (0:2 — две). Отрицательные позиции есть только у iloc.
  • Писать — только через .loc[...] = value: маска, метка или новая метка. Цепочка df[...][...] = 0 в pandas 3 ничего не меняет (Copy-on-Write), а несуществующая метка расширяет таблицу новой строкой.

01Что это и как устроено

DataFrame — таблица с двумя видами подписей: именами колонок и метками строк (индексом). loc выбирает по этим подписям, iloc — по номерам позиций. Позиция — это «который по счёту», метка — «под каким именем записан».

Отсюда два следствия. Метка переживает сортировку и фильтрацию, номер — нет: после sort_values прежняя «третья строка» уже не та. И отрицательные позиции работают (iloc[-1] — последняя строка), а отрицательных меток не бывает: loc[-1] ищет подпись −1 и падает.

🎭
Держите эту картинку в голове

Имя против номера. loc — «найти по фамилии в списке гостей»: вы не знаете, каким по счёту идёт человек, но знаете его подпись.

iloc — «взять третьего по списку»: подпись не важна, важен порядок. Поэтому «с Ивана по Ольгу» включает обоих, а «первые два» — ровно два. Метафора и внутреннее устройство — в главе 13.

03Как создать и подготовить

Для примеров хватает двух колонок и трёх строк. Если индекс не задан, pandas поставит RangeIndex — метки 0, 1, 2. Именно на нём loc и iloc неразличимы.

ref_pd_loc_lab.pypython
frame = pd.DataFrame({"amount": [1200, 800], "city": ["Москва", "Казань"]})
print(frame)
print(type(frame.index).__name__, frame.index.tolist())

named = frame.set_index("city")
print(named)
print(named.index.tolist())

back = named.reset_index()
print(back)
print(type(back.index).__name__)
amount city 0 1200 Москва 1 800 Казань RangeIndex [0, 1] amount city Москва 1200 Казань 800 ['Москва', 'Казань'] city amount 0 Москва 1200 1 Казань 800 RangeIndex

set_index("city") переносит колонку в индекс: теперь строка ищется по городу. reset_index() возвращает колонку обратно и снова нумерует строки, reset_index(drop=True) просто выбрасывает старые метки.

Индекс — это подписи, а не порядок

После set_index или сортировки метки могут идти не по возрастанию и даже повторяться. Поэтому loc по дублю возвращает все совпадения — DataFrame, а не Series.

05Разбор по группам

Все примеры страницы собраны в ref_pd_loc_lab.py: его можно запустить и менять строки. Вывод снят с прогона на pandas 3.0.1.

Одна таблица, два способа

ref_pd_loc_lab.pypython
print(df.loc["ivan", "amount"])   # подпись строки и имя колонки
print(df.iloc[1, 0])              # номер строки и номер колонки

odd = pd.DataFrame({"v": [10, 20, 30]}, index=[10, 20, 30])
print(odd.loc[30].tolist())       # строка с меткой 30
print(odd.iloc[1].tolist())       # вторая строка по счёту
800 800 [30] [20]

Оба первых вызова дают 800: loc нашёл строку по подписи ivan, iloc отсчитал вторую. Пока индекс — 0, 1, 2, способы неразличимы. На индексе [10, 20, 30] видно: loc[30] — строка с меткой 30, iloc[1] — вторая по счёту. Скаляры берут так же: at — по метке, iat — по позиции.

Срезы: где проходит граница

ref_pd_loc_lab.pypython
print(df.loc["anna":"olga"])      # правая метка включена
print(df.iloc[0:2])               # правая позиция не включена
amount city anna 1200 Москва ivan 800 Казань olga 500 Москва amount city anna 1200 Москва ivan 800 Казань

loc вернул три строки — обе метки включены. iloc вернул две: правая позиция не входит, как в списках Python. Отрицательный индекс есть только у iloc: df.iloc[-1] — последняя строка, а df.loc[-1] ищет метку −1.

Строки и колонки вместе

ref_pd_loc_lab.pypython
print(df.columns.tolist(), df.index.tolist())
print(df.loc[:, "city"].tolist())
print(df.loc[["anna", "olga"], ["amount"]])
print(df.iloc[[0, 2], [0]])
['amount', 'city'] ['anna', 'ivan', 'olga'] ['Москва', 'Казань', 'Москва'] amount anna 1200 olga 500 amount anna 1200 olga 500

У loc первый аргумент — метки строк, второй — имена колонок; iloc принимает номера и там, и там. df.loc[:, "city"] — та же колонка, что df["city"], а df[0] ищет колонку с именем 0, а не первую строку.

Маска внутри loc

ref_pd_loc_lab.pypython
print(df.loc[df["amount"] > 600, ["city", "amount"]])
city amount anna Москва 1200 ivan Казань 800

Маска — Series из True/False с индексом таблицы. loc оставляет строки с True и берёт только указанные колонки — это та же фильтрация, что разобрана на следующей странице.

Запись: маска и метка

ref_pd_loc_lab.pypython
d = df.copy()
d.loc[d["amount"] > 1000, "flag"] = True
d.loc["ivan", "amount"] = 850
print(d.to_string())
amount city flag anna 1200 Москва True ivan 850 Казань NaN olga 500 Москва NaN

Запись по маске ставит значение только прошедшим строкам, остальным достаётся NaN: pandas расширяет колонку до object. Запись по метке меняет ровно одну ячейку. Это единственный надёжный путь — df.loc[...] = value. Цепочка df[mask]["col"] = 0 таблицу не меняет (Copy-on-Write) — подробнее в ошибках.

Новая метка расширяет таблицу

ref_pd_loc_lab.pypython
d = df.copy()
d.loc["petr"] = {"amount": 700, "city": "Тверь"}
d.loc["maria", "amount"] = 450
print(d.to_string())
print(d["amount"].dtype, d.index.tolist())
amount city anna 1200.0 Москва ivan 800.0 Казань olga 500.0 Москва petr 700.0 Тверь maria 450.0 NaN float64 ['anna', 'ivan', 'olga', 'petr', 'maria']

loc не различает «заменить» и «создать»: метки нет — появится новая строка. Целая строка сохраняет типы, а присваивание по ячейке — нет: amount стала float64, чтобы вместить NaN в остальных колонках новой строки. Если расширение не задумано, это тихая ошибка.

06Три сценария из практики

Заказ по id

ref_pd_loc_lab.pypython
print(orders.loc["A-102"].to_string())
print(orders.loc["A-102", "amount"])
user ivan amount 800 800

Заказы лежат с индексом-номером. Метка — надёжный ключ: loc["A-102"] возвращает строку как Series, loc["A-102", "amount"] — одно число. После сортировки или фильтрации id не «съедет», в отличие от позиции.

Срез строк 10–20

ref_pd_loc_lab.pypython
print(big.loc[10:20, "id"].tolist())
print(big.iloc[10:21, 0].tolist())
print(len(big.loc[10:20]), len(big.iloc[10:21]))
[110, 111, 112, 113, 114, 115, 116, 117, 118, 119, 120] [110, 111, 112, 113, 114, 115, 116, 117, 118, 119, 120] 11 11

Два способа дают одно и то же: loc[10:20] — по меткам RangeIndex (20 включено), iloc[10:21] — по позициям (21 уже нет). Рабочее правило: переводите «строки с 10-й по 20-ю» в iloc[10:21], иначе потеряете последнюю.

Флаг дорогим заказам

ref_pd_loc_lab.pypython
d = df.copy()
d["vip"] = False
d.loc[d["amount"] > 1000, "vip"] = True
print(d.to_string())
amount city vip anna 1200 Москва True ivan 800 Казань False olga 500 Москва False

Флаг создают заранее (False), затем ставят True по маске. Иначе остальные строки получат NaN — как в примере с flag выше. Две строки кода вместо цикла и без риска промахнуться мимо строки.

07Пять ошибок, на которых спотыкаются

loc по номеру при строковом индексе

df.loc[0] при строковом индексе бросает KeyError: 0: 0 — это метка, а не позиция. Коварно тем, что раньше таблица могла иметь RangeIndex и код работал.

Проверьте df.index. Нужна первая строка — df.iloc[0]; нужна строка по метке — df.loc["anna"].
iloc по метке

df.iloc["anna"] бросает TypeError: Cannot index by location index with a non-integer key: iloc принимает только номера. Симметричная ошибка к предыдущей.

Имя — .loc, номер — .iloc; не заменяйте одно другим «на удачу».
Путаница включительной границы

df.loc["anna":"olga"] — три строки, а df.iloc[0:2] — две. Код, перенесённый с loc на iloc без правки границы, тихо теряет последнюю строку (или наоборот, захватывает лишнюю).

loc включает правую метку, iloc — нет. Проверяйте срез на трёх строках: loc["a":"c"] и iloc[0:3] должны совпасть.
Цепочка присваиваний

df[df["amount"] > 1000]["amount"] = 0 не меняет таблицу: промежуточный объект ведёт себя как копия. В pandas 3 (Copy-on-Write) это гарантированно, а pandas дополнительно пишет ChainedAssignmentError.

Один вызов: df.loc[df["amount"] > 1000, "amount"] = 0. Для записи всегда явный .loc.
Присваивание по несуществующей метке

df.loc["petr"] = {...} не падает, а добавляет строку; df.loc["maria", "amount"] = 450 — строку с NaN и dtype float64. Опечатка в метке превращается в новую строку.

Перед записью проверяйте "petr" in df.index или df.index.is_unique. Расширяйте таблицу только намеренно.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Чем loc отличается от iloc?

loc — выбор по метке индекса и именам колонок, iloc — по целочисленным позициям. Срезы: loc включает правую границу, iloc — нет.

Резюме: имя против номера.
Почему срез loc включает правую границу, а iloc — нет?

Метки — имена: «от anna до olga» включает обоих. Позиции — счёт, и срез 0:2 следует правилу Python: правая граница не входит.

Резюме: loc — включительно, iloc — исключительно.
Что вернёт df.loc["a"], если метка встречается дважды?

DataFrame со всеми совпавшими строками, а не Series. Код, который ждёт Series, сломается или молча получит не ту форму данных. Проверка — df.index.is_unique.

Резюме: дубль метки меняет тип результата.
Почему df[0] не выбирает первую строку?

Квадратные скобки DataFrame — это выбор колонок по имени. df[0] ищет колонку с именем 0 и падает, если её нет. Строка по позиции — df.iloc[0], строка по метке — df.loc[метка].

Резюме: скобки — для колонок, строки — через loc/iloc.
Как записать значение и почему цепочка не работает?

Только df.loc[строка, "колонка"] = value или df.loc[mask, "колонка"] = value. Цепочка df[mask]["колонка"] = value пишет в копию (Copy-on-Write).

Резюме: одна операция индексации — одна запись.

01 Строка по id и её сумма

У заказов индекс — номера. Получите строку A-103 и отдельно её сумму.

условиеpython
orders = pd.DataFrame(
    {"user": ["anna", "ivan", "olga"], "amount": [1200, 800, 500]},
    index=["A-101", "A-102", "A-103"],
)
# ожидается: строка olga и число 500
Показать решение и разбор
решениеpython
print(orders.loc["A-103"].to_string())
print(orders.loc["A-103", "amount"])
user olga amount 500 500

Что важно. Первый вызов возвращает Series, второй — скаляр. .to_string() здесь только для компактной печати.

02 Последние пять по позиции

Возьмите последние пять строк таблицы big, не зная её длины.

условиеpython
big = pd.DataFrame({"id": range(100, 125), "amount": range(25)})
# ожидается: [120, 121, 122, 123, 124]
Показать решение и разбор
решениеpython
print(big.iloc[-5:]["id"].tolist())
[120, 121, 122, 123, 124]

Что важно. Отрицательный индекс работает только у iloc: iloc[-5:] — «от пятого с конца до конца», а df.loc[-5] искал бы метку −5.

09Мостик: та же идея в SQL и NumPy

SQL: WHERE, LIMIT и UPDATE

мост в SQLsql
-- выбор по ключу: как df.loc["A-102"]
SELECT * FROM orders WHERE id = 'A-102';

-- фильтр по условию: как df.loc[mask]
SELECT * FROM orders WHERE amount > 1000;

-- запись: как df.loc[mask, "flag"] = TRUE
UPDATE orders SET flag = TRUE WHERE amount > 1000;

-- срез строк: как df.iloc[10:20]
SELECT * FROM orders ORDER BY id LIMIT 10 OFFSET 10;

loc по метке — это поиск по ключу, маска — это WHERE, iloc с позицией — LIMIT/OFFSET, а запись через loc — UPDATE. Разница в подписях: SQL не хранит позицию строки, pandas хранит индекс.

NumPy: срезы и маски

мост в NumPypython
import numpy as np

a = np.array([1200, 800, 500])
a[0:2]                        # срез: правая граница не включена — как iloc
a[a > 1000]                   # маска: как loc с условием
df.loc[df["amount"] > 1000, "amount"].to_numpy()   # pandas → NumPy

Срезы в NumPy исключительные — то же правило, что у iloc. Булева маска в NumPy — Series bool в pandas: a[a > 1000] и df[mask] — одна и та же операция отбора. Подробно — в главе 07 и главе 08.
