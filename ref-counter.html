Counter: счётчик частот Частоты, топ-N и арифметика над мультимножествами

Counter — словарь, который сам считает повторы: элемент → сколько раз. Здесь — все методы с ценой, поведение отсутствующих ключей и арифметика, которая ведёт себя не совсем как сложение чисел.

⏱ 12 минут 🎯 уровень 1–2 🐍 Python 3.12 📚 глава 06

Типы справочника: вся карта · str · list · tuple · dict · set · frozenset · Counter · defaultdict · deque

Самое главное
  • Counter — подкласс dict: ключ — элемент, значение — число повторов. Чтение отсутствующего ключа даёт 0 и не создаёт пару.
  • most_common(k) — топ-N за O(m log k); total() — сумма счётчиков, elements() — развернуть обратно в повторы.
  • Арифметика +, -, &, | работает как над мультимножествами и выбрасывает нулевые и отрицательные счётчики.

01Что это и как устроено

Counter наследуется от dict и не меняет его устройство: внутри та же хеш-таблица, ключи должны быть hashable. Разница — в том, что лежит в значениях и какие операции разрешены по умолчанию.

Ключ — элемент, значение — сколько раз он встретился. Главную работу делает __missing__: обращение к отсутствующему ключу возвращает 0, а не KeyError. При этом ключ не появляется в словаре — поэтому «прочитать» и «записать» здесь строго разные действия: c[k] ничего не меняет, а c[k] += 1 создаёт пару.

Держите эту картинку в голове

Счётчик с табло. Каждый раз, когда видите слово, щёлкаете по нему — и на табло прибавляется единица. Потом можно спросить: «что чаще всего?», «сколько всего?», «чего больше, чем вчера?».

Это первый инструмент из «ящика с инструментами» главы 06. Табло — обычный dict, просто с готовыми кнопками.

Если элемента нет в счётчике, это не авария: 0 — корректный ответ. А если ноль и минус важны как данные — Counter не подходит, он их не хранит без subtract.

03Как создать

ref_counter_lab.pypython
from collections import Counter

print(dict(Counter(["a", "b", "a"])))     # из итерируемого
print(dict(Counter({"a": 2, "b": 1})))    # из словаря
print(dict(Counter(a=3, b=1)))            # из именованных аргументов
print(dict(Counter("abracadabra")))       # строка — тоже итерируемое
print(Counter())                          # пустой счётчик
{'a': 2, 'b': 1} {'a': 2, 'b': 1} {'a': 3, 'b': 1} {'a': 5, 'b': 2, 'r': 2, 'c': 1, 'd': 1} Counter()

Из итерируемого Counter считает элементы. Из словаря он берёт готовые значения как счётчики: Counter({"a": 2}) — это «a встретился дважды», а не «есть один элемент a».

Строка — это последовательность символов

Counter("abracadabra") считает буквы. Нужны слова — сначала text.split(): Counter(text.split()). Для пар «ключ → счётчик» из списка используйте Counter(dict(pairs)), иначе Counter посчитает сами кортежи.

Четыре таблицы по назначению. «Цена» — средняя сложность в CPython, где m — число различных элементов, k — сколько элементов просят у most_common, N — длина входной последовательности.

05Разбор по группам

Все примеры страницы собраны в файле ref_counter_lab.py — его можно запустить и менять строки.

Частоты и отсутствующий ключ

ref_counter_lab.pypython
from collections import Counter

counts = Counter("abracadabra")
print(counts["a"])
print(counts["z"])               # нет ключа — 0, без KeyError
print("z" in counts)             # но ключ не создан
counts["a"] += 100               # запись как в обычном dict
print(dict(counts))
5 0 False {'a': 105, 'b': 2, 'r': 2, 'c': 1, 'd': 1}

Строка 0 False и есть главная тонкость: значение по умолчанию отдаётся, но пара не появляется. Поэтому in отвечает на вопрос «считали ли этот элемент», а не «больше ли нуля».

most_common: топ-N

ref_counter_lab.pypython
from collections import Counter

cities = ["Москва", "Казань", "Москва", "Омск", "Казань", "Москва", "Сочи"]
counts = Counter(cities)
print(counts.most_common(2))
print(counts.most_common())      # полная сортировка по убыванию
print(counts.most_common(10))    # больше, чем ключей — вернутся все
[('Москва', 3), ('Казань', 2)] [('Москва', 3), ('Казань', 2), ('Омск', 1), ('Сочи', 1)] [('Москва', 3), ('Казань', 2), ('Омск', 1), ('Сочи', 1)]

most_common(k) — это не полная сортировка: внутри heapq.nlargest, поэтому O(m log k) вместо O(m log m). При равных частотах порядок — «кто встретился раньше». Без аргумента метод сортирует всё — на большом словаре это заметно.

elements и total

ref_counter_lab.pypython
from collections import Counter

counts = Counter({"a": 2, "b": 1, "c": 0, "d": -1})
print(list(counts.elements()))   # только положительные счётчики
print(counts.total())            # сумма всех счётчиков
['a', 'a', 'b'] 2

elements() разворачивает счётчик обратно в повторы: два «a», одна «b». Нулевые и отрицательные значения он молча пропускает, а total() их суммирует — 2 + 1 + 0 + (−1) = 2. Эти две операции отвечают на разные вопросы, не путайте.

update и subtract

ref_counter_lab.pypython
from collections import Counter

counts = Counter({"python": 2, "sql": 1})
counts.update(["python", "pandas"])   # складывает, а не заменяет
counts.update({"sql": 2})
print(dict(counts))

counts.subtract({"python": 3, "sql": 10})   # вычитает и уходит в минус
print(dict(counts))
{'python': 3, 'sql': 3, 'pandas': 1} {'python': 0, 'sql': -7, 'pandas': 1}

Оба метода меняют счётчик на месте и возвращают None. update прибавляет, subtract вычитает — в отличие от оператора -, они оставляют нули и минусы. В update можно передать итерируемое (тогда считаются элементы) или mapping (тогда складываются счётчики).

Арифметика: +, -, &, |

ref_counter_lab.pypython
from collections import Counter

a = Counter({"python": 3, "sql": 1})
b = Counter({"python": 1, "sql": 2})
print(dict(a + b))    # складывает счётчики
print(dict(a - b))    # вычитает, неположительные выбрасывает
print(dict(a & b))    # минимум по каждому ключу
print(dict(a | b))    # максимум по каждому ключу
{'python': 4, 'sql': 3} {'python': 2} {'python': 1, 'sql': 1} {'python': 3, 'sql': 2}

Это операции над мультимножествами: у каждого элемента есть кратность, и & — пересечение (минимум), | — объединение (максимум). Практический смысл: a - b — «чего не хватает», a & b — «что есть у обоих».

Нули, минусы и унарные операторы

ref_counter_lab.pypython
from collections import Counter

a = Counter({"python": 4, "sql": 1})
b = Counter({"python": 1, "sql": 5})
print(dict(a - b))            # sql ушёл в минус — пара исчезла

a.subtract(b)                 # subtract меняет на месте
print(dict(a))                # нули и минусы остаются
print(a.total())              # total() суммирует всё, включая минусы

c = Counter({"a": 2, "b": 0, "c": -3})
print(dict(+c))               # унарный + — только положительные
print(dict(-c))               # унарный - — знак меняется, мусор отброшен
print(Counter({"a": 0}) == Counter())
{'python': 3} {'python': 3, 'sql': -4} -1 {'a': 2} {'c': 3} True

Три разных поведения, которые легко перепутать: оператор - создаёт новый Counter и выбрасывает неположительные пары; subtract() меняет на месте и сохраняет нули и минусы; унарные + и - оставляют только положительные. А равенство игнорирует нулевые счётчики: Counter({"a": 0}) и пустой Counter — равны.

copy и clear

ref_counter_lab.pypython
from collections import Counter

counts = Counter("abracadabra")
copy = counts.copy()
counts.clear()
print(copy["a"], len(counts), len(copy))
5 0 5

copy() даёт независимый счётчик: очистка исходного на копию не влияет. Копия поверхностная — как у dict, но значения здесь числа, так что на практике этого достаточно.

06Три сценария из практики

Частоты статусов заказов

ref_counter_lab.pypython
from collections import Counter

statuses = ["new", "paid", "new", "shipped", "paid", "new", "cancelled"]
by_status = Counter(statuses)
print(dict(by_status))
print(by_status.most_common(2))
print(by_status.total())
{'new': 3, 'paid': 2, 'shipped': 1, 'cancelled': 1} [('new', 3), ('paid', 2)] 7

Один проход по данным — и есть и распределение, и топ, и общее число. В pandas это value_counts(), в SQL — GROUP BY … COUNT(*). total() здесь заодно проверяет, что ничего не потеряли: сумма частот равна длине списка.

Топ-N городов

ref_counter_lab.pypython
from collections import Counter

city_orders = ["Москва", "Казань", "Москва", "Омск", "Казань",
               "Москва", "Сочи", "Москва", "Омск", "Казань"]
top = Counter(city_orders).most_common(3)
print(top)
for city, n in top:
    print(f"{city}: {n}")
[('Москва', 4), ('Казань', 3), ('Омск', 2)] Москва: 4 Казань: 3 Омск: 2

most_common(3) не сортирует весь список городов — берёт три максимума. Для миллионов различных ключей это разница между секундами и миллисекундами. Дальше пары уже готовы к выводу или к вставке в отчёт.

Сравнение двух наборов

ref_counter_lab.pypython
from collections import Counter

warehouse = Counter({"яблоко": 10, "груша": 5, "слива": 8})
sold = Counter({"яблоко": 12, "груша": 3, "слива": 8})
print(dict(warehouse - sold))   # чего не хватает на складе
print(dict(sold - warehouse))   # переизбыток
print(dict(warehouse & sold))   # пересечение мультимножеств
print(warehouse == sold)        # равенство частот
{'груша': 2} {'яблоко': 2} {'яблоко': 10, 'груша': 3, 'слива': 8} False

Мультимножество — это «сколько чего»: warehouse - sold показывает, чего не хватило, sold - warehouse — что продали сверх остатка. Нули и минусы в результат не попадают, поэтому «слива» исчезла из разности: её ровно столько же.

07Пять ошибок, на которых спотыкаются

most_common() без n на больших данных

Без аргумента метод сортирует все ключи — O(m log m). «Дай топ-10» из миллиона различных элементов превращается в полную сортировку.

Всегда указывайте most_common(10): внутри heapq, O(m log k).
Нехешируемые элементы

Counter([[1], [2]]) падает с TypeError: unhashable type: 'list': Counter — словарь, а ключ должен быть hashable.

Кортежи вместо списков: Counter([(1, 2), (3, 4)]).
Отрицательные счётчики после subtract

c.subtract(d) может увести значение в минус. Дальше elements() такие пары пропускает, most_common() ставит их в конец, а in продолжает говорить «ключ есть».

Проверяйте значение: c.get(k, 0) > 0; обнулить хвост — c = +c.
Ждать от c - d нулей

Оператор - не оставляет пару со счётчиком 0 — он её удаляет. Код, который потом делает c[k] == 0 или рассчитывает на все ключи, получает KeyError или неполный словарь.

Нужны нули — subtract() (меняет на месте) или обычный dict с явной арифметикой.
Путать update и subtract

update складывает, subtract вычитает. Вторая тонкость: update с итерируемым считает элементы, а не пары — список [("a", 1)] добавит ключ-кортеж, а не прибавит единицу к «a».

Пары передавайте словарём: c.update({"a": 1}); элементы — итерируемым.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Чем Counter отличается от обычного dict?

Counter — подкласс dict, но с счётной семантикой: отсутствующий ключ на чтение даёт 0 без KeyError, есть most_common, elements, total и арифметика над мультимножествами.

Резюме: dict + готовые операции счёта.
Почему counts["missing"] не бросает KeyError и появляется ли ключ?

Counter переопределяет __missing__: чтение отсутствующего ключа возвращает 0, но не вставляет пару. Ключ появится, только если записать явно: counts["missing"] += 1.

Резюме: 0 на чтение — да, ключ в словаре — нет.
Что делает most_common(k) и сколько это стоит?

Возвращает k самых частых пар по убыванию. Внутри — heapq.nlargest, то есть O(m log k); без аргумента — полная сортировка O(m log m). При равных частотах порядок определяется первым появлением элемента.

Резюме: есть k — дешёвый топ; нет k — дорогая сортировка.
Чем subtract() отличается от оператора -?

subtract() меняет счётчик на месте, возвращает None и сохраняет нули и отрицательные значения. Оператор - возвращает новый Counter и выбрасывает все неположительные пары. Иногда именно это и нужно, но ожидать «ключа со значением 0» от оператора нельзя.

Резюме: subtract — «оставить историю», минус — «оставить только плюсы».
Как Counter сравнивает два набора?

Как мультимножества: сравнение == учитывает счётчики, но игнорирует нулевые. a - b — «чего не хватает», a & b — «что есть у обоих в минимальном количестве», a | b — максимум по каждому элементу.

Резюме: те же операции, что у set, только с кратностями.

01 Топ-3 слова

Найдите три самых частых слова в тексте. Регистр не важен.

условиеpython
text = "SQL python sql pandas python SQL"
# ожидается: [('sql', 3), ('python', 2), ('pandas', 1)]
Показать решение и разбор
решениеpython
from collections import Counter

text = "SQL python sql pandas python SQL"
counts = Counter(text.lower().split())
print(counts.most_common(3))
[('sql', 3), ('python', 2), ('pandas', 1)]

Что важно. lower() нормализует регистр до подсчёта, а не после. most_common(3) сразу даёт топ и не сортирует весь словарь. Если нужны доли, делите на total().

02 Анаграммы

Проверьте, являются ли две строки анаграммами: те же буквы с теми же кратностями.

условиеpython
def is_anagram(a, b):
    ...

# is_anagram("listen", "Silent") → True
# is_anagram("abc", "abbc")      → False
Показать решение и разбор
решениеpython
from collections import Counter

def is_anagram(a: str, b: str) -> bool:
    return Counter(a.lower()) == Counter(b.lower())

print(is_anagram("listen", "Silent"))
print(is_anagram("abc", "abbc"))
True False

Что важно. Сравнение Counter — это сравнение мультимножеств: «abc» и «abbc» дают разные счётчики, поэтому False. lower() делает проверку регистронезависимой; пробелы и пунктуацию при необходимости убирают до подсчёта.

09Мостик: та же идея в pandas и SQL

pandas: value_counts

мост в pandaspython
import pandas as pd

df = pd.DataFrame({"city": ["Москва", "Казань", "Москва"], "amount": [1200, 800, 500]})

df["city"].value_counts()                 # Counter: ключ → частота, уже по убыванию
df["city"].value_counts(normalize=True)   # то же, но доли от суммы
df.groupby("city").size()                 # Counter через groupby

value_counts() — это most_common(), который сразу возвращает Series: индекс — значения, данные — частоты. Параметр normalize=True заменяет деление на total().

SQL: GROUP BY и COUNT(*)

мост в SQLsql
-- Counter: частоты и топ-N
SELECT city, COUNT(*) AS orders
FROM orders
GROUP BY city
ORDER BY orders DESC
LIMIT 3;

-- то же, но только те, что встречаются чаще двух раз
SELECT city, COUNT(*) AS orders
FROM orders
GROUP BY city
HAVING COUNT(*) > 2;

GROUP BY — это Counter на стороне базы: ключ — группа, значение — агрегат. ORDER BY … DESC LIMIT повторяет most_common(k), а HAVING — фильтр по счётчику, аналог c[k] > 2.
