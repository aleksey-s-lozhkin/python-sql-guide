Индексация и маски: трафарет поверх сетки Срезы, булевы маски, fancy-indexing и np.where — что view, а что копия

Достать из сетки нужные клетки можно тремя способами: рамкой (срез), трафаретом (маска) и списком номеров (fancy). Они по-разному ведут себя в памяти и возвращают разную форму. Здесь — полная шпаргалка: что вернёт операция, что изменится в исходнике и где ловушка синтаксиса.

Самое главное
  • Базовая индексация — числа, срезы, : — возвращает view: окно в те же данные. Изменили срез — изменился исходный массив.
  • Продвинутая — маска, список индексов, np.take — возвращает копию: новые данные в новой памяти, исходник цел.
  • Условия соединяются только &, |, ~ и всегда в скобках; np.where не фильтрует, а выбирает значение для каждой клетки.

01Что это и как устроено

Индексация отвечает на вопрос «какие клетки сетки нужны». В NumPy два принципиально разных механизма. Базовый — числа, срезы и : — считает новую форму и новые strides по старым данным, поэтому возвращает view. Продвинутый — булева маска или список индексов — собирает выбранные элементы в новый буфер, то есть возвращает копию.

Маска — это массив bool той же формы, что исходник, или одномерный по длине оси. Внутри неё ровно то же сравнение, что вернуло ages > 25: True — клетка попала под прорезь. Результат фильтра всегда одномерный: форма при отборе по значениям теряется.

Fancy-indexing — выбор по номерам: arr[[0, 2]] берёт элементы 0 и 2, а grid[[0, 2], [1, 0]] — пары координат (0, 1) и (2, 0). Это тоже копия, поэтому менять результат безопасно для исходника.

🪟
Держите эту картинку в голове

Маска — это трафарет с прорезями. Вы накрываете им сетку данных: видно только то, что попало под прорези. Трафарет либо той же формы, что сетка, либо одномерный по длине оси — иначе он просто не ляжет.

Срез — это рамка. Она показывает прямоугольную область («строки 1–2, столбцы 2–3»), не спрашивая про значения. Рамка и трафарет — разные инструменты, и путать их — типичная ошибка. Метафору целиком разбирает глава 08, а цену view и copy — глава 11.

NaN не равен сам себе, поэтому values > 2 не отличит пропуск от маленького числа: для пропусков есть np.isnan. А and/or работают с одним значением истинности и на массивах падают — нужны &, |, ~.

03Как взять кусок

ref_np_indexing_lab.pypython
import numpy as np

ages = np.array([22, 31, 25, 40, 19])
grid = np.array([[1, 2, 3], [4, 5, 6]])
print(ages[1:4])
print(ages[ages > 25])
print(ages[[0, 2]])
print(grid[0, 1])
[31 25 40] [31 40] [22 25] 2

Три способа — три разных результата по смыслу: срез ages[1:4] берёт диапазон, маска ages[ages > 25] — по значению, список ages[[0, 2]] — по номерам. Для двумерного это же работает с координатами: grid[0, 1] — клетка строки 0, столбца 1.

Рамка и трафарет в одной записи

В одном индексе можно смешивать: grid[1:, [0, 2]] — срез по строкам плюс список столбцов. Но если в индексе есть маска или список, NumPy уже не может вернуть view: результат — копия.

05Разбор по группам

Все примеры страницы — в файле ref_np_indexing_lab.py (нужен numpy 2.3.5).

Срезы: рамка по осям

ref_np_indexing_lab.pypython
ages = np.array([22, 31, 25, 40, 19])
print(ages[1:4])
print(ages[-2:])
print(ages[::-1])
print(ages[::2])

grid = np.array([[1, 2, 3], [4, 5, 6]])
print(grid[0])
print(grid[:, 1])
print(grid[1:, ::2])

window = ages[1:4]
window[0] = 99
print(ages)
[31 25 40] [40 19] [19 40 25 31 22] [22 25 19] [1 2 3] [2 5] [[4 6]] [22 99 25 40 19]

Формула та же, что у списка: [start:stop:step], где stop не включается. grid[0] — строка (view), grid[:, 1] — столбец (тоже view), а grid[1:, ::2] — подматрица из последней строки и чётных столбцов. Запись window[0] = 99 изменила ages: срез — это окно, а не копия.

Маски и np.where

ref_np_indexing_lab.pypython
ages = np.array([22, 31, 25, 40, 19])
mask = ages > 25
print(mask, mask.dtype)
print(ages[mask])

salaries = np.array([50000, 90000, 70000, 120000, 45000])
both = (ages > 25) & (salaries > 60000)
print(both)
print(ages[both])

print(ages[(ages < 25) | (ages > 35)])
print(ages[~(ages > 25)])

print(np.where(ages > 25, "adult", "young"))
print(np.where(ages > 25, 1, 0))
print(np.where(ages > 25))

low = np.array([1, 2, 3, 4, 5])
high = np.array([10, 20, 30, 40, 50])
print(np.where(ages > 25, high, low))
[False True False True False] bool [31 40] [False True False True False] [31 40] [22 40 19] [22 25 19] ['young' 'adult' 'young' 'adult' 'young'] [0 1 0 1 0] (array([1, 3]),) [ 1 20 3 40 5]

Сравнение возвращает новый массив bool той же формы — сам по себе он ничего не фильтрует. Отбор даёт одномерный массив: ages[mask] теряет исходный порядок осей, но сохраняет порядок элементов. Условия соединяются &, | и ~, и каждое условие — в скобках: у & приоритет выше сравнения. np.where — не фильтр, а выбор: форма результата та же, что у условия.

Fancy-indexing, take, clip, nonzero

ref_np_indexing_lab.pypython
ages = np.array([22, 31, 25, 40, 19])
picked = ages[[0, 2, 4]]
print(picked)

picked[0] = 99
print(ages)
print(picked)

grid = np.array([[1, 2, 3], [4, 5, 6]])
print(grid[[1, 0]])
print(grid[[0, 1], [2, 0]])

print(np.take(ages, [4, 0]))
print(np.clip(ages, 25, 35))
print(np.nonzero(ages > 25))
print(np.argwhere(ages > 25))
[22 25 19] [22 31 25 40 19] [99 25 19] [[4 5 6] [1 2 3]] [3 4] [19 22] [25 31 25 35 25] (array([1, 3]),) [[1] [3]]

Список номеров даёт копию: picked[0] = 99 не тронул ages. Для матриц grid[[1, 0]] переставляет строки, а grid[[0, 1], [2, 0]] берёт пары координат — клетки (0, 2) и (1, 0), то есть [3, 4]. np.take делает то же функцией, np.clip обрезает значения до границ, а nonzero/argwhere возвращают индексы, а не значения.

Ошибки индексации

ref_np_indexing_lab.pypython
ages = np.array([22, 31, 25, 40, 19])
try:
    ages[np.array([True, False])]
except IndexError as e:
    print(type(e).__name__, str(e).split(";")[0])

try:
    (ages > 25) and (ages < 35)
except ValueError as e:
    print(type(e).__name__, str(e).split(".")[0])

print(ages[[]], ages[[]].shape)
ages[[]] = 999
print(ages)
IndexError boolean index did not match indexed array along axis 0 ValueError The truth value of an array with more than one element is ambiguous [] (0,) [22 31 25 40 19]

Маска обязана совпасть по длине с осью: два флага на пять элементов — ошибка. Оператор and требует одного значения истинности, а у массива их пять — отсюда ValueError и правило про &. Пустой список индексов — не ошибка: результат пустой, а присваивание по нему ничего не делает.

06Три сценария из практики

Заказы дороже 1000

ref_np_indexing_lab.pypython
users = np.array(["Anna", "Olga", "Ivan", "Anna", "Olga"])
amounts = np.array([1200, 800, 1500, 500, 300])
mask = amounts > 1000
print(users[mask])
print(amounts[mask].sum())
print(np.where(mask, amounts, 0))
['Anna' 'Ivan'] 2700 [1200 0 1500 0 0]

Одна маска применяется и к именам, и к суммам — они выровнены по одной оси. Сумма отобранных заказов — 2700, а np.where оставляет форму исходного массива, заменяя ненужное нулём.

Два условия: возраст и зарплата

ref_np_indexing_lab.pypython
ages = np.array([22, 31, 25, 40, 19])
salaries = np.array([50000, 90000, 70000, 120000, 45000])
mask = (ages > 25) & (salaries > 60000)
print(mask)
print(ages[mask], salaries[mask])
[False True False True False] [31 40] [ 90000 120000]

«И» — это &, и оба условия в скобках. Такой же фильтр в pandas — df[(df.age > 25) & (df.salary > 60000)], в SQL — WHERE age > 25 AND salary > 60000.

Категории через where

ref_np_indexing_lab.pypython
scores = np.array([68, 92, 81, 55])
labels = np.where(scores >= 80, "high", "low")
print(labels)
print(np.where(scores >= 80, scores, 0))
['low' 'high' 'high' 'low'] [ 0 92 81 0]

Когда нужен не отбор, а категория для каждой клетки, берут np.where: он сохраняет форму и возвращает новый массив. Это прямой аналог CASE WHEN в SQL.

07Пять ошибок, на которых спотыкаются

Маска не той формы

ages[np.array([True, False])] для пяти элементов бросает IndexError: boolean index did not match indexed array along axis 0: флагов должно быть столько же, сколько клеток по оси.

Стройте маску из самого массива: mask = ages > 25. Для двумерного — та же форма, что у массива, иначе фильтруйте по строкам отдельно.
and вместо &

(ages > 25) and (ages < 35) бросает ValueError: The truth value of an array with more than one element is ambiguous: Python пытается свести массив к одному True/False.

(ages > 25) & (ages < 35) — и обязательно в скобках: у & приоритет выше, чем у >.
Ждать view от fancy-indexing

arr[[0, 2]] — копия, а не окно. Изменение результата исходник не трогает; это не ошибка Python, а неверная модель памяти.

Нужно писать в исходник — используйте срез или arr[mask] = .... Проверять связь помогает np.shares_memory (страница 05).
Сюрприз пустого индекса

ages[[]] не падает: это пустой результат формы (0,), а ages[[]] = 999 ничего не меняет. На первый взгляд — «ошибка должна быть».

Проверяйте длину результата (.size == 0) и не полагайтесь на исключение как на сигнал «ничего не выбрано».
Забыть, что срез — view

window = ages[1:4]; window[0] = 99 меняет ages: срез не копирует данные. Особенно опасно при передаче «куска» в функцию, которая пишет в массив.

Нужна независимость — ages[1:4].copy(). Проверка — np.shares_memory.

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем срез отличается от маски?

Срез задаёт прямоугольную область по номерам осей и возвращает view: данные общие. Маска задаёт набор клеток по значению, может дать произвольный набор элементов и возвращает копию — форма при этом становится одномерной.

Резюме: рамка говорит «где», трафарет — «какие».
Почему (ages > 25) & (ages < 35) в скобках?

У & приоритет выше, чем у сравнения: без скобок выражение прочитается как ages > (25 & (ages < 35)). А and не подходит вовсе: он сворачивает массив к одному значению истинности и падает с ValueError.

Резюме: массивная логика — только &, |, ~ и в скобках.
Чем fancy-indexing отличается от среза по памяти?

Срез — view: новый заголовок на тот же буфер. Список индексов и np.take — копия: NumPy собирает выбранные элементы в новый массив, потому что они могут идти в произвольном порядке.

Резюме: срез смотрит, список — копирует.
Чем np.where(cond, a, b) отличается от arr[cond]?

arr[cond] отбрасывает элементы и меняет форму — остаётся одномерный набор подходящих. np.where(cond, a, b) сохраняет форму и для каждой клетки выбирает a или b: это замена значения, а не фильтр.

Резюме: маска выкидывает, where заменяет.
Почему arr[[]] не ошибка?

Пустой список индексов — законный fancy-index: выбрано ноль элементов, результат формы (0,). Присваивание по пустому индексу просто не находит, куда писать, и ничего не меняет.

Резюме: пустой выбор — не ошибка, проверяйте .size.

01 Чётные числа

Оставьте из массива только чётные числа и посчитайте их сумму.

условиеpython
nums = np.array([3, 8, 12, 5, 7, 10])
# ожидается: [ 8 12 10] 30
Показать решение и разбор
решениеpython
mask = nums % 2 == 0
print(nums[mask], nums[mask].sum())
[ 8 12 10] 30

Что важно. nums % 2 == 0 — маска той же формы; индексация ею даёт копию только с чётными, sum() считает итог. Исходный массив не меняется.

02 Порог через where

Пометьте температуру как «hot», если она не ниже 20, иначе «cold» — не меняя форму массива.

условиеpython
temps = np.array([12, 25, 8, 30])
# ожидается: ['cold' 'hot' 'cold' 'hot']
Показать решение и разбор
решениеpython
print(np.where(temps >= 20, "hot", "cold"))
['cold' 'hot' 'cold' 'hot']

Что важно. np.where возвращает массив той же длины, что и условие, — форма сохранена. Это аналог CASE WHEN ... THEN ... ELSE ... END.

09Мостик: та же идея в pandas и SQL

pandas: маска и loc

мост в pandaspython
import pandas as pd

df = pd.DataFrame({"user": ["Anna", "Olga", "Ivan"],
                   "amount": [1200, 800, 1500]})
df[df["amount"] > 1000]                   # та же маска
df.loc[df["amount"] > 1000, "user"]       # маска + колонка
df.loc[[0, 2]]                            # fancy по позициям
df["amount"].where(df["amount"] > 1000, 0)  # np.where

В pandas маска — такая же серия значений bool, а .loc принимает её вместе с колонками. Отличие в том, что у таблицы есть подписи строк, поэтому фильтр сохраняет исходный индекс, а не просто позиции. Подробнее — глава 14 и глава 13.

SQL: WHERE и CASE WHEN

мост в SQLsql
-- маска: amounts > 1000
SELECT * FROM orders WHERE amount > 1000;

-- два условия: (amount > 1000) & (user IN ('Anna', 'Olga'))
SELECT * FROM orders
WHERE amount > 1000 AND user IN ('Anna', 'Olga');

-- where как категория: CASE WHEN
SELECT id,
       CASE WHEN amount > 1000 THEN 'big' ELSE 'small' END AS size
FROM orders;

WHERE — это маска, AND — это & (только без скобок, потому что сравниваются скаляры строки), а CASE WHEN повторяет np.where. Разница в том, что SQL фильтрует строки таблицы, а NumPy — клетки массива.
