Фильтрация: маска как сито Маски, условия и NaN: как отобрать строки и не потерять пропуски

Фильтрация — это WHERE в мире pandas. Маска — такой же объект, как колонка: Series из True и False длиной с таблицу. Здесь собрано всё, что нужно для отбора: &, |, ~, isin, between, query и отдельный разговор про пропуски.

Самое главное
  • Маска — это Series из bool той же длины, что таблица. df[mask] оставляет строки с True и возвращает новую таблицу, а не вид на старую.
  • Условия соединяются поэлементно: &, |, ~, и каждое сравнение — в скобках. and/or на Series падают: ValueError: The truth value of a Series is ambiguous.
  • NaN не проходит ни одно сравнение: строка с пропуском не попадёт ни в > 600, ни в <= 600. Для пропусков — isna()/notna(), для подстроки — str.contains(..., na=False).

01Что это и как устроено

Сравнение колонки с числом применяется к каждому элементу и даёт Series из bool с тем же индексом. Индексация df[mask] оставляет строки, где значение истинно, — и только их. Маска не «живёт внутри» таблицы: это отдельный объект, который можно сохранить, сложить с другой маской и посчитать.

Результат фильтра — новая таблица. В pandas 3 действует Copy-on-Write, поэтому правка отфильтрованной копии не меняет исходную; а логика над масками — поэлементная, как в NumPy: &, |, ~.

🫗
Держите эту картинку в голове

Маска — это сито с дырками. Таблица просыпается через него: строки, где условие истинно, проходят; остальные остаются сверху и отбрасываются.

Сито имеет ровно ту же форму, что таблица. Не «фильтр где-то внутри», а отдельный объект длиной с таблицу — поэтому его можно посчитать: mask.sum() покажет, сколько строк прошло. Подробный разбор — в главе 14.

03Как создать и подготовить

Маску создаёт сравнение или метод, который возвращает bool. В таблице специально есть пропуск в amount: на нём видны все ловушки с NaN.

ref_pd_filter_lab.pypython
mask = df["amount"] > 1000
print(mask)
print(type(mask).__name__, mask.dtype, len(mask))
print(df[mask].to_string())
0 True 1 False 2 False 3 False Name: amount, dtype: bool Series bool 4 user amount city email 0 anna 1200.0 Москва anna@mail.ru

mask — Series, а не «фильтр внутри»: она хранит True/False для каждой строки. Поэтому её можно посчитать: mask.sum() — сколько строк прошло, mask.mean() — их доля.

NaN не проходит ни одно сравнение

Строка с пропуском не попадёт ни в amount > 600, ни в amount <= 600: сравнение с NaN даёт False. Это не баг, а семантика пропуска — для него есть isna().

05Разбор по группам

Все примеры страницы собраны в файле ref_pd_filter_lab.py — его можно запустить и менять строки. Вывод ниже снят с реального прогона на pandas 3.0.1.

Маска и выбор колонок

ref_pd_filter_lab.pypython
print(df.loc[df["amount"] > 1000, ["user", "city"]].to_string())
print(df[df["amount"] > 1000]["user"].tolist())
user city 0 anna Москва ['anna']

df[mask] отдаёт все колонки, df.loc[mask, [...]] — только перечисленные. Второй вариант и читается лучше, и не тащит лишние данные через всю цепочку.

Логика: &, |, ~ и скобки

ref_pd_filter_lab.pypython
both = (df["amount"] > 600) & (df["city"] == "Москва")
print(both.tolist())
print(df[both].to_string())

print(df[(df["city"] == "Казань") | (df["amount"] > 1000)]["user"].tolist())
print(df[~df["city"].isin(["Москва"])]["user"].tolist())
[True, False, False, False] user amount city email 0 anna 1200.0 Москва anna@mail.ru ['anna', 'ivan'] ['ivan', 'petr']

Каждое сравнение — в своих скобках: у & приоритет выше, чем у >. ~ инвертирует готовую маску, поэтому применяется к isin(...), а не к колонке.

isin и between

ref_pd_filter_lab.pypython
print(df[df["city"].isin(["Казань", "Тверь"])]["user"].tolist())
print(df["amount"].between(800, 1200).tolist())
print(df[df["amount"].between(800, 1200)]["user"].tolist())
['ivan', 'petr'] [True, True, False, False] ['anna', 'ivan']

isin — точное сравнение с любым значением из списка (SQL IN), between — диапазон, и обе границы включены: 800 и 1200 проходят. Пропуск в between даёт False, а не NaN.

Текст: contains и na

ref_pd_filter_lab.pypython
print(df["city"].str.contains("Мос").tolist())
print(df[df["city"].str.contains("Мос", na=False)]["user"].tolist())
print(df[df["user"].str.contains("an")]["user"].tolist())
[True, False, True, False] ['anna', 'olga'] ['anna', 'ivan']

contains по умолчанию работает как regex: точка — любой символ, для буквальной подстроки нужен regex=False. В pandas 3 колонка строк имеет dtype str, и пропуск уже даёт False; na=False делают намерение явным и спасают object-колонки, где маска содержит None.

Пропуски: isna и notna

ref_pd_filter_lab.pypython
print(df[df["amount"].isna()].to_string())
print(df["amount"].notna().tolist())
print(df["amount"].isna().sum())
user amount city email 3 petr NaN Тверь petr@corp.ru [True, True, True, False] 1

isna() и notna() — единственный корректный способ искать пропуски. Сравнение == np.nan всегда False, даже для строки, где NaN действительно лежит.

query и filter по колонкам

ref_pd_filter_lab.pypython
print(df.query("amount > 600 and city == 'Москва'").to_string())
limit = 600
print(df.query("amount > @limit")["user"].tolist())
print(df.filter(like="am", axis=1).columns.tolist())
user amount city email 0 anna 1200.0 Москва anna@mail.ru ['anna', 'ivan'] ['amount']

query читается ближе к SQL, но строки внутри — не Python-код: переменные передаются через @, а сложные выражения надёжнее писать маской. filter(axis=1) отбирает колонки по имени — это не фильтр строк.

Топ-N и дубли

ref_pd_filter_lab.pypython
print(df.nlargest(2, "amount")[["user", "amount"]].to_string())
print(df.sort_values("amount", ascending=False).head(2)["user"].tolist())
print(df.drop_duplicates(subset="city")["user"].tolist())
user amount 0 anna 1200.0 1 ivan 800.0 ['anna', 'ivan'] ['anna', 'ivan', 'petr']

nlargest — дешёвый топ-N без полной сортировки, NaN он игнорирует. sort_values(...).head(n) нужен, когда важен сам порядок. drop_duplicates(subset=...) оставляет первое вхождение каждого значения и не трогает остальные строки.

NaN и арифметика маски

ref_pd_filter_lab.pypython
print((df["amount"] == np.nan).tolist())
print((df["amount"] > 600).tolist())
print((df["amount"] <= 600).tolist())

mask = df["amount"] > 600
print(mask.sum(), mask.mean())
print(f"{mask.mean():.2f}")
[False, False, False, False] [True, True, False, False] [False, False, True, False] 2 0.5 0.50

Пропуск не «больше» и не «меньше» — он просто не проходит условие. Поэтому строка с NaN исчезает из результата и прямого, и обратного фильтра. А сама маска — числа 0 и 1: sum считает прошедшие строки, mean — их долю.

06Три сценария из практики

Дорогие заказы

ref_pd_filter_lab.pypython
expensive = df[df["amount"] > 600]
print(expensive[["user", "amount"]].to_string())

user amount 0 anna 1200.0 1 ivan 800.0 2000.0

Сначала маска, потом выбор колонок — сумму можно считать по отфильтрованной таблице. sum пропускает NaN, поэтому строка petr не превращает итог в NaN.

Города из списка

ref_pd_filter_lab.pypython
cities = ["Москва", "Тверь"]
print(df[df["city"].isin(cities)].to_string())
user amount city email 0 anna 1200.0 Москва anna@mail.ru 2 olga 500.0 Москва olga@mail.ru 3 petr NaN Тверь petr@corp.ru

Список городов приходит из конфига или API — isin принимает его как есть. Цепочка сравнений через | работала бы так же, но на десятке значений становится нечитаемой; isin — это SQL IN.

Email содержит домен

ref_pd_filter_lab.pypython
print(df[df["email"].str.contains("mail.ru", regex=False)]["user"].tolist())
print(df[df["email"].str.endswith("@mail.ru")]["user"].tolist())
['anna', 'olga'] ['anna', 'olga']

regex=False обязателен, если в шаблоне есть точка: иначе она означает «любой символ» и найдёт лишнее. endswith строже — проверяет конец строки, — но точка в домене всё равно требует regex=False.

07Пять ошибок, на которых спотыкаются

and и or вместо & и |

(df["amount"] > 600) and (df["city"] == "Москва") бросает ValueError: The truth value of a Series is ambiguous: and требует одного True/False, а в Series их тысячи. or ведёт себя так же.

Поэлементные &, |, ~ — те же операторы, что в NumPy.
Забытые скобки

df["amount"] > 600 & (df["city"] == "Москва") не падает: у & приоритет выше, поэтому сначала считается 600 & mask (получается 0), и выражение превращается в amount > 0. Вернутся три строки вместо одной — и без ошибки.

Каждое сравнение — в скобках: (a > 1) & (b == "x").
Цепочка присваиваний

df[df["amount"] > 1000]["amount"] = 0 не меняет таблицу: промежуточный объект — копия. В pandas 3 (Copy-on-Write) это гарантированно, а pandas пишет ChainedAssignmentError.

Один вызов: df.loc[df["amount"] > 1000, "amount"] = 0.
Сравнение с NaN

df["amount"] == np.nan всегда False, даже для строки, где NaN действительно лежит. И > 600, и <= 600 дают для неё False — строка исчезает из любого фильтра.

Для пропусков — isna() / notna(), а не сравнение.
in по колонке вместо isin

"anna" in df["user"] возвращает False: in по Series проверяет индекс, а не значения. Проверка по df["user"].values работает, но это O(n) на каждую строку цикла — на большой таблице получается O(n²).

df["user"].isin(["anna"]) — векторно и правильно; отрицание — ~.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Что такое маска и почему это не «фильтр внутри»?

Маска — Series из True/False длиной с таблицу и с тем же индексом. df[mask] оставляет строки с True; маску можно посчитать.

Резюме: сито длиной с таблицу.
Почему and не работает, а & работает?

and сводит выражение к одному True/False, а в Series значений много — отсюда ValueError. & — поэлементная операция, как в NumPy, и возвращает новую маску.

Резюме: логика над массивами — поэлементная.
Чем df[mask] отличается от df.loc[mask, "col"]?

Первое возвращает все колонки, второе — только указанные. Строки фильтруются одинаково: маска остаётся первым аргументом, колонки — вторым.

Резюме: строки — маска, колонки — второй аргумент.
Почему строки с NaN исчезают при фильтрации?

Сравнение с NaN всегда False, поэтому строка не проходит ни прямое, ни обратное условие. Это семантика пропуска, а не баг: для отбора пропусков есть isna().

Резюме: NaN не «больше» и не «меньше».
Чем isin отличается от contains?

isin проверяет точное равенство любому значению из списка, contains ищет подстроку (по умолчанию регуляркой) внутри значения. isin — для категорий, contains — для текста.

Резюме: список целиком против куска строки.

01 Москва дороже 600

Оставьте заказы из Москвы дороже 600 и выведите только user и amount.

условиеpython
df = pd.DataFrame(
    {"user": ["anna", "ivan", "olga", "petr"],
     "amount": [1200.0, 800.0, 500.0, np.nan],
     "city": ["Москва", "Казань", "Москва", "Тверь"]},
)
# ожидается: одна строка — anna
Показать решение и разбор
решениеpython
mask = (df["amount"] > 600) & (df["city"] == "Москва")
print(df.loc[mask, ["user", "amount"]].to_string())
user amount 0 anna 1200.0

Что важно. Два сравнения в скобках, между ними &, а не and; маска идёт первым аргументом loc, колонки — вторым.

02 Найти и посчитать пропуски

Для той же таблицы найдите пользователя с пропущенной суммой и посчитайте долю таких строк.

условиеpython
# та же таблица df
# ожидается: ['petr'] и 0.25
Показать решение и разбор
решениеpython
print(df[df["amount"].isna()]["user"].tolist())
print(df["amount"].isna().mean())
['petr'] 0.25

Что важно. isna() — такая же маска, как сравнение, поэтому её можно и подставить в df[...], и усреднить: доля True и есть доля пропусков.

09Мостик: та же идея в SQL и NumPy

SQL: WHERE и его родственники

мост в SQLsql
SELECT * FROM orders WHERE amount > 600;              -- df[mask]
SELECT * FROM orders WHERE city IN ('Москва', 'Тверь'); -- isin
SELECT * FROM orders WHERE amount BETWEEN 600 AND 1200; -- between
SELECT * FROM orders WHERE email LIKE '%mail.ru';       -- str.contains
SELECT * FROM orders WHERE amount IS NULL;              -- isna

Каждой конструкции pandas соответствует SQL-оператор. Разница — в пропусках: ~isin([...]) сохраняет строки с NaN, а SQL NOT IN с NULL в подзапросе может вернуть пустой результат (главы 20 и 22).

NumPy: трафарет поверх сетки

мост в NumPypython
import numpy as np

a = np.array([1200.0, 800.0, 500.0, np.nan])
a > 600            # [True, True, False, False] — та же маска
a[a > 600]         # отбор значений — как df[mask]
np.isnan(a)        # маска пропусков — как isna()

Маска NumPy — «трафарет поверх сетки»: вы накрываете им массив и видите только True. Series bool в pandas устроена так же, поэтому a[a > 600] и df[mask] — одна операция отбора. Разбор трафарета — в главе 08.
