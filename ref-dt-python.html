Самое главное
  • datetime — момент (дата + время), date — день, time — время суток, timedelta — длительность. Все четыре типа неизменяемые.
  • naive не знает зону, aware знает (несёт tzinfo). Вычитать и сравнивать можно только одинаковые; epoch — это секунды, не ms.
  • ISO-строка — общий язык обмена: isoformat() и fromisoformat(). Для поясов — zoneinfo.ZoneInfo, а не фиксированный offset.

01Что это и как устроено

datetime — неизменяемый объект, который хранит поля настенных часов: год, месяц, день, час, минуту, секунду, микросекунду — и, если повезёт, tzinfo. Без tzinfo объект naive: его 14:30 — это «где-то 14:30», без привязки к зоне. С tzinfo — aware: момент знает, как он относится к UTC.

date хранит только день, time — только время суток (и тоже может быть aware), timedelta — длительность в днях, секундах и микросекундах. Отдельно живёт epoch — число секунд от 1970-01-01T00:00:00Z; это уже не дата, а число.

⏳
Держите эту картинку в голове

Линия времени, отрывной календарь и песочные часы. datetime — точка на линии: aware-точка знает, где именно она на линии, naive — только показывает настенные часы. date — лист отрывного календаря: один день, без времени. timedelta — песочные часы: не точка, а количество времени, которое можно пересыпать.

Аргументы у datetime позиционные и необязательные: можно передать только дату — время станет 00:00:00. timedelta нормализует всё в дни, секунды и микросекунды, поэтому 2 дня 3 часа 30 минут печатаются как 2 days, 3:30:00.

now() и today() — только для реального времени

datetime.now() и date.today() читают системные часы. На странице они не используются — все примеры на фиксированных датах, чтобы вывод не менялся. В коде читайте их один раз на границе приложения.

naive и aware

from datetime import datetime, timezone
from zoneinfo import ZoneInfo
naive = datetime(2024, 3, 15, 14, 30)

replace(tzinfo=...) не переводит время, а вешает ярлык зоны на те же 14:30; перевод момента, а не ярлыка, — это astimezone() ниже.

ISO-строки: isoformat и fromisoformat

ref_dt_python_lab.pypython
from datetime import datetime, timezone
raw = "2024-03-15T14:30:00+03:00"
dt = datetime.fromisoformat(raw)
print(dt)
print(dt.isoformat())
print(dt.astimezone(timezone.utc).isoformat())
print(datetime.fromisoformat("2024-03-15T11:30:00Z"))
2024-03-15 14:30:00+03:00 2024-03-15T14:30:00+03:00 2024-03-15T11:30:00+00:00 2024-03-15 11:30:00+00:00

fromisoformat() сохраняет смещение: строка с +03:00 даёт aware-объект, а astimezone(utc) — тот же момент в UTC. Суффикс Z — синоним +00:00 (с 3.11).

epoch: timestamp и fromtimestamp

from datetime import datetime, timezone
stamp = 1704067200

print(dt.isoformat())

epoch — число секунд от 1970-01-01 UTC. 1704067200 — это полночь 1 января 2024 года. timestamp() возвращает float; fromtimestamp принимает секунды. Если передать миллисекунды, момент уедет в 55969 год — об этом в ошибках. Для воспроизводимости fromtimestamp вызывают с явным tz.

astimezone: перевод между зонами

ref_dt_python_lab.pypython
from datetime import datetime, timezone
from zoneinfo import ZoneInfo
utc = datetime(2024, 3, 15, 11, 30, tzinfo=timezone.utc)
moscow = utc.astimezone(ZoneInfo("Europe/Moscow"))
berlin = utc.astimezone(ZoneInfo("Europe/Berlin"))
print(utc.isoformat())
print(moscow.isoformat())
print(berlin.isoformat())
print(moscow == berlin)
2024-03-15T11:30:00+00:00 2024-03-15T14:30:00+03:00 2024-03-15T12:30:00+01:00 True

Один и тот же момент — 11:30 UTC — в Москве 14:30, а в Берлине 12:30. Настенные часы разные, момент один, поэтому moscow == berlin истинно: aware-сравнение идёт по абсолютному времени. astimezone() меняет зону, не меняя момент; replace(tzinfo=...), наоборот, меняет ярлык, не меняя поля.

Разность дат даёт timedelta, у неё .days — целые дни. replace собирает новую дату из полей — удобно для «первое число месяца»; если поле станет некорректным (30 февраля), будет ValueError.

DST: несуществующее и неоднозначное время

ref_dt_python_lab.pypython
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo
berlin = ZoneInfo("Europe/Berlin")
spring = datetime(2024, 3, 31, 2, 30, tzinfo=berlin)
print(spring.isoformat())
print(spring.astimezone(timezone.utc).isoformat())
print(spring.astimezone(timezone.utc).astimezone(berlin).isoformat())
fall0 = datetime(2024, 10, 27, 2, 30, tzinfo=berlin, fold=0)
fall1 = datetime(2024, 10, 27, 2, 30, tzinfo=berlin, fold=1)
print(fall0.isoformat(), fall0.utcoffset())
print(fall1.isoformat(), fall1.utcoffset())
w = datetime(2024, 3, 30, 12, tzinfo=berlin)
print((w + timedelta(days=1)).isoformat())
next_utc = w.astimezone(timezone.utc) + timedelta(days=1)
print(next_utc.astimezone(berlin).isoformat())
2024-03-31T02:30:00+01:00 2024-03-31T01:30:00+00:00 2024-03-31T03:30:00+02:00 2024-10-27T02:30:00+02:00 2:00:00 2024-10-27T02:30:00+01:00 1:00:00 2024-03-31T12:00:00+02:00 2024-03-31T13:00:00+02:00

В Берлине 31 марта 2024 года 02:30 не существует: часы прыгают с 02:00 на 03:00. datetime(...) всё равно создаст объект — он молча возьмёт смещение до перехода (+01:00), а перевод в UTC и обратно даст 03:30 (+02:00). Осенью 27 октября 02:30 существует дважды: различаются fold=0 (+02:00) и fold=1 (+01:00). Наконец, прибавление timedelta(days=1) к aware-времени сохраняет настенное время (12:00 → 12:00), а прибавление суток в UTC сдвигает его на 13:00.

API присылает ISO-строку со смещением; fromisoformat даёт aware-момент. Дальше два решения: хранить как есть или привести к UTC и хранить момент — второй вариант обычно удобнее для базы и сравнений.

TTL и интервал

ref_dt_python_lab.pypython
from datetime import datetime, timedelta, timezone
created = datetime(2024, 3, 15, 14, 30, tzinfo=timezone.utc)
ttl = timedelta(hours=1, minutes=30)
expires = created + ttl
check_at = datetime(2024, 3, 15, 15, 45, tzinfo=timezone.utc)
print(created.isoformat())
print(expires.isoformat())
print(check_at < expires)
print((expires - created).total_seconds())
2024-03-15T14:30:00+00:00 2024-03-15T16:00:00+00:00 True 5400.0

timedelta — естественный TTL: момент создания плюс длительность; проверка «истёк ли» — сравнение двух aware-моментов. total_seconds() переводит длительность в секунды — 1:30 — это 5400 секунд. Если сравнивать naive с aware, будет TypeError, поэтому обе границы должны быть в одной зоне.

Группировка по месяцам

from datetime import datetime
stamps = [

07Пять ошибок, на которых спотыкаются

naive и aware в одной операции

naive - aware падает с TypeError: can't subtract offset-naive and offset-aware datetimes: Python не знает, в какой зоне трактовать naive-объект.

Привести обе стороны к одной зоне: dt.replace(tzinfo=tz) для naive или astimezone(tz) для aware.
Миллисекунды вместо секунд в epoch

timestamp() и fromtimestamp() считают секунды. Передали 1704067200000 — получили год 55969 и ValueError: year ... is out of range (на других платформах — OSError).

Миллисекунды делить на 1000: ts / 1000; наоборот — умножать и округлять.
strptime без формата и с локалью

strptime требует шаблон и точное совпадение: для "15.03.2024" шаблон %Y-%m-%d даст ValueError: time data does not match format. Шаблоны с %B/%A зависят от локали процесса.

Хранить и передавать ISO-8601; для разбора — fromisoformat или точный числовой формат.
Несуществующее время при переходе на летнее

31 марта 2024 в Берлине 02:30 не существует, но datetime(...) не падает: объект получает смещение +01:00, а после перевода в UTC и обратно оказывается 03:30. Код «молча получает другое время».

Работать в UTC, а в локальную зону переводить только для вывода; проверять round-trip через astimezone.
now() в тестах и кэше

datetime.now() внутри функции делает результат недетерминированным: тесты «плавают», кэш зависит от запуска, а вчерашний баг не воспроизводится.

Передавать момент параметром (now=datetime.now(tz)) или подменять часы в тесте; в примерах — фиксированные даты.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Чем naive datetime отличается от aware?

Naive не имеет tzinfo и означает «настенные часы без зоны». Aware несёт tzinfo и знает смещение от UTC, поэтому его можно сравнивать и вычитать с другими aware-моментами.

Резюме: naive — картинка часов, aware — точка на линии времени.
Зачем zoneinfo.ZoneInfo, если есть timezone(timedelta(hours=3))?

timezone(timedelta(...)) — фиксированное смещение: оно не знает про переходы на летнее время и меняющиеся правила стран. ZoneInfo берёт правила из базы IANA и сам выбирает смещение для конкретной даты.

Резюме: фиксированный offset — для UTC и редких случаев, зона — для людей.
Чем isoformat/fromisoformat отличаются от strftime/strptime?

ISO-пара — стандартный машинный формат: isoformat() и fromisoformat() понимают друг друга без шаблона. strftime/strptime — произвольный шаблон: гибко для человека, но формат нужно держать в двух местах и он зависит от локали.

Резюме: ISO — для обмена, strftime — для показа.
timestamp() — это секунды или миллисекунды?

Секунды, тип float. Миллисекунды — это timestamp() * 1000; в fromtimestamp их нужно делить на 1000, иначе год уезжает в далёкое будущее.

Резюме: epoch в Python — секунды.
Почему 31 марта 02:30 в Берлине — проблема?

В этот момент часы переводятся вперёд, и такого настенного времени не существует. datetime не падает, а выбирает смещение до перехода; потом момент «переезжает» на 03:30. Осенью наоборот: 02:30 существует дважды, и различие задаёт fold.

Резюме: локальное время неоднозначно — считайте в UTC.

print(deadline > start)
17 1468800.0 True

Что важно. Разность двух date — это timedelta; .days даёт целые дни (17), total_seconds() — секунды (1468800.0). Для дат без времени достаточно date: меньше шансов запутаться в зонах.

09Мостик: pandas, SQL и соседние страницы

pandas: Timestamp и .dt

datetime → pandaspython
import pandas as pd
s = pd.Series(["2024-03-15T14:30:00+03:00"])
ts = pd.to_datetime(s, utc=True)       # разбор + приведение к UTC
ts.dt.tz_convert("Europe/Moscow")      # аналог astimezone
ts.dt.floor("D")                       # начало дня
ts.dt.month, ts.dt.day                 # поля, как .month и .day

pd.Timestamp — наследник datetime, а datetime64[ns] хранит моменты компактно. .dt — аксессор с полями и методами; tz_localize вешает зону (как replace(tzinfo=...)), tz_convert переводит (как astimezone). Подробно — страница 03.

SQL: date, timestamp, timestamptz

datetime → SQLsql
-- timestamptz хранит момент (внутри — UTC)
SELECT created_at AT TIME ZONE 'Europe/Moscow' AS msk
FROM orders;
-- арифметика: дата + интервал
SELECT created_at + INTERVAL '1 day' AS next_day
FROM orders;

date — день, timestamp — настенные часы, timestamptz — момент; строкой хранят, только если нужен «сырой» текст — иначе теряются сравнение, сортировка и зона. INTERVAL — timedelta базы; тонкости — на странице 04.
