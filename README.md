# Ассоциативный гайд: Python → pandas → SQL

Учебный гайд для backend-разработчика по программе на 8 недель. Не набор конспектов, а
**одна система понятий**: одни и те же ментальные модели (хеш-таблица, «разложить — посчитать —
собрать», «оглавление книги») работают в Python, pandas и SQL.

Книга — статический сайт: без сервера, без сборки, без интернета. Открывается на ноутбуке
двойным щелчком, а на телефоне — с домашнего экрана и **читается офлайн** после первого визита.

## Открыть

```
open guide/index.html
```

## Практика (сервис)

Помимо книги есть отдельный сервис: аккаунты, синхронизация прогресса и **проверка SQL-задач
на живой базе** (результат сравнивается с эталоном, а не текст запроса).

```bash
cd deploy
cp .env.example .env
docker compose up -d --build
open http://localhost:8080
```

Подробно — [deploy/README.md](deploy/README.md): домен, Caddy и TLS, бэкапы, обновления.
Код — `app/` (FastAPI + PostgreSQL), задачи — `app/data/tasks/*.yaml`.

Статус: MVP работает локально (регистрация, вход, прогресс, 4 задачи). Проверка:
`bash tools/check_service.sh http://127.0.0.1:8080` — 16 проверок, включая запрет DROP и доступ к `app`.
Следующее — больше задач, синхронизация прогресса с книгой и публикация на домене.

## Телефон и офлайн

1. Опубликуйте книгу на GitHub Pages (ниже) — нужен `https`, иначе браузер не включит офлайн-кэш.
2. Откройте ссылку на телефоне и полистайте 2–3 страницы: service worker скачает все 170 файлов.
3. Safari: «Поделиться → На экран «Домой»»; Chrome: меню → «Установить приложение».
4. Дальше книга открывается без сети. Прогресс чтения и размер текста (А−/А+) запоминаются.

Место чтения не теряется: позиция сохраняется автоматически (при переключении и сворачивании),
на обложке есть карточка «Продолжить чтение» и список закладок, а в установленном приложении
последняя глава открывается сразу при запуске (галочка на обложке отключает это).

Закладка ставится кнопкой 🔖 в правом нижнем углу главы — она появится на обложке и вернёт
ровно в это место.

Статус кэша виден в сайдбаре: «офлайн-копия готова». При открытии файлом (`file://`) офлайн-кэш
не работает — это ограничение браузера, а не книги.

## Принципы

1. **Одна модель — три технологии.** Если тема встречается в Python, pandas и SQL, глава
   показывает её трижды, а не три отдельных главы.
2. **Код проверен запуском.** Вывод в главах получен прогоном на этой машине (Python 3.12,
   numpy 2.3.5, pandas 3.0.1), а не написан «по памяти».
3. **Мало текста, много структуры.** Глава: зачем → ассоциация-якорь → ряд из 8 звеньев → схема →
   лаборатория → мост → ошибки → вопросы → задачи → чек-лист.
4. **Уровни владения.** Узнаю / применяю / объясняю. Переход к следующей теме — после «применяю»,
   ключевые темы — до «объясняю».
5. **Ответ как на интервью.** Каждый вопрос разобран по схеме «тезис → механика → ограничение».

## Публикация на GitHub Pages

1. Репозиторий запушен в `main`.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch → `gh-pages` / (root)**.
3. Workflow `.github/workflows/pages.yml` при каждом пуше в `main` заново собирает ветку `gh-pages`
   из папки `guide/`.
4. Адрес: `https://<user>.github.io/<repo>/` — он же для телефона.

Публикация идёт через ветку `gh-pages`, а не через artifact-деплой: artifact-вариант
иногда падает с ошибкой «No artifacts named github-pages», а ветку можно собрать локально
тем же скриптом — `tools/publish.sh`.

## Как расширять гайд

Структура данных — в `guide/assets/toc.js`; там три независимых списка. Ниже — что куда
добавлять, чтобы книга оставалась целой. Прогресс «освоено глав» считает только
`BOOK.chapters` (26 глав программы), поэтому дополнения и справочники его не ломают.

### 1. Глава программы (`chapters`)

1. Написать `guide/ch-NN-slug.html` по шаблону главы 02.
2. В `guide/assets/toc.js` добавить запись в `chapters` с `part` и `ready: true`.
3. Добавить схему в `guide/assets/maps/` и лабораторию в `guide/snippets/`.
4. Вписать лабораторию в `guide/appendix-snippets.html`; проверить мостики из соседних глав.
5. `node tools/gen_sw.cjs`, `node tools/check-links.cjs`, запуск лаборатории.

### 2. Спецглава / дополнение (`extras`)

Темы вне 8-недельной программы, которые не должны её переставлять (пример — глава 27).

1. Написать страницу `guide/ch-NN-slug.html` в том же шаблоне; в `eyebrow` — `Дополнение · вне недель`.
2. В `guide/assets/toc.js` добавить запись в `extras` (номер 27+, `desc: "Спецглава · вне недель"`).
3. Сайдбар и обложка подхватят её автоматически: группа «Дополнения», счётчик глав не меняется.
4. Добавить лабораторию и строку в `guide/appendix-snippets.html`.
5. `node tools/gen_sw.cjs`, `node tools/check-links.cjs`, проверки.

### 3. Справочник (`reference`)

1. Создать хаб `guide/appendix-<тема>.html` (карта, «цена», конвертации, карточки страниц).
2. Добавить в `guide/assets/toc.js` запись хаба (`hub: true`, `group: "<тема>"`, `nav: "<короткое имя>"`)
   и страницы `ref-<тема>-*.html` с тем же `group`. Сайдбар и активные состояния — автоматически.
3. Добавить лаборатории и строки в `guide/appendix-snippets.html`; поставить ссылки из глав-источников.
4. `node tools/gen_sw.cjs`, `node tools/check-links.cjs`, `node tools/pwa-check.cjs`,
   `node tools/verify.cjs light`/`dark`; затем коммит и пуш (публикация — GitHub Actions).

### Общее правило

Один источник правды — `toc.js`; страницы только ссылаются друг на друга. Новая страница
обязательна в `toc.js`, иначе `check-links` её не увидит, а офлайн-кэш не обновит `gen_sw.cjs`.
