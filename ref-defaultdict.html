defaultdict: блокнот с группами Фабрика значений, чтение-вставка и группировка без проверок

defaultdict — словарь, у которого для каждого нового ключа уже заготовлено значение по умолчанию. Здесь — как работает default_factory, что именно создаёт чтение и почему get ведёт себя иначе.

⏱ 12 минут 🎯 уровень 1–2 🐍 Python 3.12 📚 глава 06

Типы справочника: вся карта · str · list · tuple · dict · set · frozenset · Counter · defaultdict · deque

Самое главное
  • defaultdict — подкласс dict с фабрикой: чтение отсутствующего ключа вызывает default_factory, вставляет результат и возвращает его.
  • get(), setdefault() и update() фабрику не зовут — «посмотреть» и «создать» остаются разными операциями.
  • Удобен для группировки (list), сумм (int), графов и вложенных словарей; расплата — неявные вставки и проблемы с pickle.

01Что это и как устроено

defaultdict — это dict с одной добавленной идеей: у него есть default_factory — вызываемый объект, который создаёт значение для отсутствующего ключа. Всё остальное — хеш-таблица, порядок вставки, методы — наследуется от обычного словаря.

Когда вы пишете d[key], а ключа нет, dict вызывает __missing__. У defaultdict этот метод зовёт фабрику, кладёт результат в словарь и возвращает его. Поэтому группировка пишется одной строкой: groups[user].append(amount) — страница «user» создаётся сама, вместе с пустым списком.

Держите эту картинку в голове

Блокнот с предзаполненными страницами. Открываете страницу «Anna» — а там уже пустой список, в который можно писать. Не нужно проверять, заведена ли страница: блокнот заводит её при первом открытии.

Это второй инструмент из «ящика с инструментами» главы 06. Важная деталь: страница создаётся именно при открытии — даже если вы только заглянули.

03Как создать

ref_defaultdict_lab.pypython
from collections import defaultdict

print(defaultdict(list))                 # фабрика — list
print(defaultdict(int)["missing"])       # фабрика int → 0
d = defaultdict(list, {"Anna": [1200]})  # можно сразу с данными
print(dict(d))
print(defaultdict(None))                 # фабрики нет
defaultdict(<class 'list'>, {}) 0 {'Anna': [1200]} defaultdict(None, {})

Первый аргумент конструктора — фабрика: list, int, set, dict или любой вызываемый объект без обязательных аргументов. Второй (необязательный) — данные, как у обычного dict: словарь или пары.

defaultdict(42) — ошибка сразу

Конструктор проверяет вызываемость: defaultdict(42) падает с TypeError: first argument must be callable or None. А присваивание d.default_factory = 42 пройдёт молча — ошибка вылезет только при чтении отсутствующего ключа.

04Все методы и операции

Своих методов у defaultdict почти нет — он наследует всё от dict и добавляет поведение при чтении. «Цена» — как у словаря, где m — число пар.

Создание и фабрика

05Разбор по группам

Все примеры страницы собраны в файле ref_defaultdict_lab.py — его можно запустить и менять строки.

Чтение создаёт ключ

ref_defaultdict_lab.pypython
from collections import defaultdict

d = defaultdict(int)
print(d["x"])            # фабрика int() → 0
print("x" in d)          # ключ уже в словаре
print(d.get("y"))        # get фабрику не зовёт
print("y" in d)          # и ключ не создаёт
print(dict(d))
0 True None False {'x': 0}

Вот и вся механика: d["x"] — это не «посмотреть», а «получить или создать». get — «только посмотреть». Разница в одну букву, а последствия разные: после чтения через [] проверка "x" in d уже не отвечает на вопрос «был ли ключ раньше».

default_factory: атрибут и None

ref_defaultdict_lab.pypython
from collections import defaultdict

d = defaultdict(list)
print(d.default_factory)
d["a"].append(1)
print(dict(d))

d.default_factory = int          # фабрика меняется на лету
print(d["b"])
print(dict(d))

plain = defaultdict(None)        # фабрики нет — ведёт себя как dict
try:
    plain["x"]
except KeyError as e:
    print("KeyError", e)
<class 'list'> {'a': [1]} 0 {'a': [1], 'b': 0} KeyError 'x'

default_factory — обычный атрибут: его можно прочитать и заменить на другую фабрику. Если фабрика None, словарь ведёт себя как обычный dict и бросает KeyError на отсутствующий ключ.

Унаследованные методы dict

ref_defaultdict_lab.pypython
from collections import defaultdict

d = defaultdict(int, {"a": 1})
print(d.get("b"))                # None, ключ не создан
print(d.setdefault("c", 5))      # фабрика не вызывается
print(d.pop("a"))
print(list(d.items()))
d.update({"e": 7})
print(dict(d))
None 5 1 [('c', 5)] {'c': 5, 'e': 7}

Важно: setdefault("c", 5) создал ключ со значением 5, а не 0 — фабрика в этом методе не участвует. pop, items, update, len, views — всё работает ровно как у dict.

copy() сохраняет фабрику

ref_defaultdict_lab.pypython
from collections import defaultdict

d = defaultdict(list, {"Anna": [1200]})
copy = d.copy()
copy["Ivan"].append(800)
print(dict(copy))
print(copy.default_factory is list)
copy["Anna"].append(500)         # копия поверхностная
print(dict(d))
{'Anna': [1200], 'Ivan': [800]} True {'Anna': [1200, 500]}

Копия — defaultdict с той же фабрикой, а не обычный dict. Но копирование поверхностное: списки внутри общие, поэтому copy["Anna"].append(500) меняет и исходный словарь.

__missing__: точка расширения

ref_defaultdict_lab.pypython
from collections import defaultdict

class Logged(defaultdict):
    def __missing__(self, key):
        print("создаю", key)
        return super().__missing__(key)

d = Logged(list)
d["Anna"].append(1200)
d["Anna"].append(500)
print(dict(d))
создаю Anna {'Anna': [1200, 500]}

Через __missing__ поведение можно донастроить: логировать, ограничивать, подставлять computed-значение. Метод вызывается только когда ключа нет — второе обращение к «Anna» прошло мимо него.

pickle: lambda против partial

ref_defaultdict_lab.pypython
import functools
import pickle
from collections import defaultdict

try:
    pickle.dumps(defaultdict(lambda: 0))
except Exception as e:
    print(type(e).__name__)

nested = defaultdict(functools.partial(defaultdict, int))
nested["Anna"]["x"] += 1
restored = pickle.loads(pickle.dumps(nested))
print(restored["Anna"]["x"])
print(restored["Ivan"]["y"])     # фабрика восстановилась
print(type(restored.default_factory).__name__)
PicklingError 1 0 partial

lambda нельзя сериализовать: у неё нет имени, по которому pickle мог бы её найти. functools.partial(defaultdict, int) — обычный объект с именем и аргументами, он переживает pickle; после восстановления фабрика снова работает.

06Три сценария из практики

Группировка и суммы по пользователям

ref_defaultdict_lab.pypython
from collections import defaultdict

orders = [
    ("Anna", 1200),
    ("Ivan", 800),
    ("Anna", 500),
    ("Olga", 1500),
]
by_user = defaultdict(list)
totals = defaultdict(int)
for user, amount in orders:
    by_user[user].append(amount)
    totals[user] += amount

print(dict(by_user))
print(dict(totals))
print(sorted(totals.items(), key=lambda kv: kv[1], reverse=True))
{'Anna': [1200, 500], 'Ivan': [800], 'Olga': [1500]} {'Anna': 1700, 'Ivan': 800, 'Olga': 1500} [('Anna', 1700), ('Olga', 1500), ('Ivan', 800)]

Ровно две строки в цикле, и нет ни одной проверки «а есть ли уже ключ». Для сумм — defaultdict(int), для списков — defaultdict(list). Если нужен только счётчик количества, короче взять Counter.

Граф и инверсия словаря

ref_defaultdict_lab.pypython
from collections import defaultdict

edges = [("Anna", "Ivan"), ("Anna", "Olga"), ("Ivan", "Olga")]
graph = defaultdict(list)
for a, b in edges:
    graph[a].append(b)
    graph[b].append(a)          # неориентированный граф
print(dict(graph))

prices = {"apple": 120, "pear": 90, "plum": 120}
by_price = defaultdict(list)
for name, price in prices.items():
    by_price[price].append(name)
print(dict(by_price))
{'Anna': ['Ivan', 'Olga'], 'Ivan': ['Anna', 'Olga'], 'Olga': ['Anna', 'Ivan']} {120: ['apple', 'plum'], 90: ['pear']}

Список смежности — классическое применение: у каждой вершины сразу есть список соседей. Инверсия словаря — то же самое, только группы строятся по значению; если значения уникальны, хватит comprehension'а из справочника по dict.

Вложенные defaultdict

ref_defaultdict_lab.pypython
from collections import defaultdict

orders = [("Москва", 2023), ("Казань", 2023), ("Москва", 2024), ("Москва", 2024)]
by_city_year = defaultdict(lambda: defaultdict(int))
for city, year in orders:
    by_city_year[city][year] += 1

print(dict(by_city_year["Москва"]))
print(dict(by_city_year["Казань"]))
print(by_city_year["Омск"][2024])   # создалась целая ветка
print(sorted(by_city_year))
{2023: 1, 2024: 2} {2023: 1} 0 ['Казань', 'Москва', 'Омск']

Внешняя фабрика создаёт внутренний defaultdict на каждый новый город, внутренняя — счётчик. Обратите внимание на предпоследнюю строку: чтение by_city_year["Омск"] создало целую ветку, и «Омск» появился в sorted(...). Для pickle вместо lambda используйте functools.partial(defaultdict, int).

07Пять ошибок, на которых спотыкаются

Чтение создаёт ключ

if d[key]: или отладочный print(d[key]) добавляет ключ в словарь. После этого key in d истинно, а len(d) вырос — проверки начинают врать.

Для «только посмотреть» — d.get(key); для накопления — осознанно d[key].
default_factory = None (или невызываемый)

С defaultdict(None) чтение отсутствующего ключа бросает KeyError. А присваивание невызываемого объекта в default_factory проходит молча и падает с TypeError только при первом чтении.

Фабрика — list, int, set, dict или функция без обязательных аргументов; проверяйте d.default_factory.
Фабрика возвращает один и тот же объект

defaultdict(lambda: shared_list) подставит один список во все ключи: дописали в одну группу — изменились все. Так же ломается «общая» вложенность, если внутренний объект создан снаружи.

Фабрика должна создавать новый объект на каждый вызов: list, int, set, functools.partial(defaultdict, int).
lambda и pickle

pickle.dumps(defaultdict(lambda: 0)) падает с PicklingError: lambda нельзя сериализовать. Многопроцессность, кэш на диск и очередь задач с таким словарём не переживут передачу.

Именованная функция или functools.partial(defaultdict, int); для JSON — dict(d) (фабрика в JSON не сохраняется в принципе).
Считать фабрику частью данных

Равенство defaultdict(list, {"a": 1}) == {"a": 1} — истинно: фабрика не учитывается. JSON-сериализация тоже её теряет. Если логика зависит от фабрики, это нужно проверять явно.

Сравнивайте d.default_factory отдельно; для хранения и передачи используйте обычный dict или данные.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Что делает defaultdict при чтении отсутствующего ключа?

Вызывает __missing__, который зовёт фабрику, вставляет результат в словарь и возвращает его. Поэтому чтение через [] меняет словарь, а get — нет.

Резюме: чтение = «получить или создать».
Чем d[k] отличается от d.get(k) и d.setdefault(k, default)?

d[k] создаёт значение фабрикой и вставляет ключ. get(k) возвращает None и ничего не создаёт. setdefault(k, default) создаёт ключ, но со значением default, а не с результатом фабрики.

Резюме: [] — фабрика, get — смотреть, setdefault — свой default.
Где хранится фабрика и можно ли её поменять?

В атрибуте default_factory. Его можно прочитать и заменить на другую фабрику; можно даже присвоить None — тогда словарь станет вести себя как обычный dict. Конструктор проверяет вызываемость, а присваивание — нет.

Резюме: фабрика — настройка словаря, а не часть данных.
Почему defaultdict(list) не всегда заменяет setdefault?

setdefault(key, []) создаёт список, только когда вы сами попросили, и не срабатывает при чтении. defaultdict(list) создаёт пустой список при любом чтении отсутствующего ключа, даже случайном. Если пустые группы нежелательны — setdefault безопаснее.

Резюме: defaultdict удобнее, но вставляет неявно.
Какие ловушки у вложенных defaultdict и pickle?

Вложенность задаётся фабрикой, которая должна создавать новый словарь на каждый ключ: defaultdict(lambda: defaultdict(int)) или functools.partial(defaultdict, int). Lambda не сериализуется — для pickle и многопроцессности берите partial или именованную функцию.

Резюме: фабрика — «рецепт нового значения», и рецепт должен быть именуемым.

01 Группировка по длине слова

Разложите слова по длине: ключ — длина, значение — список слов.

условиеpython
words = ["sql", "python", "dbt", "pandas", "go", "api"]
# ожидается: {3: ['sql', 'dbt', 'api'], 6: ['python', 'pandas'], 2: ['go']}
Показать решение и разбор
решениеpython
from collections import defaultdict

words = ["sql", "python", "dbt", "pandas", "go", "api"]
by_len = defaultdict(list)
for word in words:
    by_len[len(word)].append(word)
print(dict(by_len))
{3: ['sql', 'dbt', 'api'], 6: ['python', 'pandas'], 2: ['go']}

Что важно. by_len[len(word)].append(word) — ключ создаётся первым же обращением, список приходит из фабрики. Порядок ключей — порядок первого появления длины, поэтому 3, 6, 2, а не 2, 3, 6.

02 Степени вершин

Посчитайте количество связей у каждой вершины неориентированного графа.

условиеpython
edges = [("Anna", "Ivan"), ("Anna", "Olga"), ("Ivan", "Olga"), ("Olga", "Ivan")]
# ожидается: {'Anna': 2, 'Ivan': 3, 'Olga': 3}
Показать решение и разбор
решениеpython
from collections import defaultdict

edges = [("Anna", "Ivan"), ("Anna", "Olga"), ("Ivan", "Olga"), ("Olga", "Ivan")]
degree = defaultdict(int)
for a, b in edges:
    degree[a] += 1
    degree[b] += 1
print(dict(degree))
{'Anna': 2, 'Ivan': 3, 'Olga': 3}

Что важно. defaultdict(int) избавляет от проверки «первая ли это связь вершины»: degree[a] += 1 сам создаёт нулевой счётчик. Если бы вершина встречалась только как второй конец ребра, она всё равно попала бы в словарь.

09Мостик: та же идея в pandas и SQL

pandas: groupby

мост в pandaspython
import pandas as pd

df = pd.DataFrame({"user": ["Anna", "Ivan", "Anna"], "amount": [1200, 800, 500]})

df.groupby("user")["amount"].sum()        # defaultdict(int): суммы по группам
df.groupby("user")["amount"].apply(list)  # defaultdict(list): группы целиком
df.groupby("user").groups                 # словарь «группа → индексы строк»

groupby — это defaultdict плюс агрегация: ключ — значение столбца, значение — группа строк. .groups буквально отдаёт словарь группа → метки, а .apply(list) собирает группы так же, как defaultdict(list).

SQL: GROUP BY и array_agg

мост в SQLsql
-- defaultdict(int): сумма по группам
SELECT user_id, SUM(amount) AS total
FROM orders
GROUP BY user_id;

-- defaultdict(list): собрать значения группы в массив
SELECT user_id, array_agg(amount) AS amounts
FROM orders
GROUP BY user_id;

GROUP BY — тот же аккумулятор по ключу, только внутри базы. array_agg играет роль defaultdict(list), SUM — роль defaultdict(int). Группы создаются из данных, и «пустых» групп, как при чтении defaultdict, здесь не бывает.
