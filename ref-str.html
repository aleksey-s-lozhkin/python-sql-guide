str — неизменяемая последовательность символов: у каждого есть номер, но саму нить перевязать нельзя. Здесь полный набор методов с ценой, нормализация, разбиение и сборка, форматирование, кодировки, проверки is* и пять ошибок, которые встречаются в проде.

Типы справочника: вся карта · str · list · tuple · dict · set · frozenset · Counter · defaultdict · deque

Самое главное
  • str — неизменяемая последовательность символов: индекс O(1), срез O(k) и всегда новая строка. Отдельного типа «символ» нет — s[0] возвращает str длины 1.
  • Все «изменяющие» методы — upper, strip, replace — возвращают новый str. strip режет набор символов с краёв, а removeprefix — ровно префикс.
  • Сборка — sep.join(...), а не + в цикле; поиск — in или find; сравнение без учёта регистра — casefold.

01Что это и как устроено

Строка — упорядоченная и неизменяемая последовательность символов Unicode. «Упорядоченная» значит, что у каждого символа есть номер и по нему можно попасть сразу. «Неизменяемая» — что сам объект поменять нельзя: любая «правка» собирает новую строку.

Внутри CPython 3.12 строка хранится компактно: для латиницы хватает байта на символ, для кириллицы — двух. Поэтому len и доступ по индексу — O(1), а срез копирует k символов в новую строку. Длина считается в кодовых точках: len("🇷🇺") → 2, потому что флаг собран из двух символов-индикаторов.

Неизменяемость — гарантия, а не ограничение: строку можно положить в ключ словаря и не бояться, что её изменят под рукой. Плата — каждая «правка» выделяет новый объект и копирует символы.

Держите эту картинку в голове

Бусы из символов. Символы нанизаны по порядку: у каждой бусины есть номер, и по номеру её видно сразу, без перебора. Но готовую нить не перевязать — любая «правка» собирает новые бусы.

Номер бусины — это индекс: s[5000] стоит столько же, сколько s[0]. Срез — новая нить из k бусин. А «замена символа» — всегда новые бусы: все методы возвращают новый str. Изменяемую версию той же последовательности разбирает глава 03: list — те же бусы, но с разъёмными замками.

Кавычки — не часть строки

print показывает строку как есть, а repr — как литерал: с кавычками и экранированием. Поэтому ниже repr стоит там, где важны пробелы на краях: иначе ' anna ' и 'anna' на экране выглядят одинаково.

capitalize поднимает только первую букву строки, title — каждое слово. Для сравнения мало lower: ß превращается в ss только при casefold, поэтому "STRASSE" и "straße" совпадают лишь после него. strip("x") — не «убрать префикс», а «срезать все символы из набора {x} с обоих концов»; removeprefix убирает ровно одну подстроку и только если она совпала.

casefold — для сравнения, не для вывода

casefold — агрессивный lower для caseless matching: логины, email, поиск по названиям. Он может вернуть строку, непохожую на исходную, поэтому показывать результат не стоит — только сравнивать.

maxsplit ограничивает число разрезов: split(";", 1) режет один раз слева, rsplit(";", 1) — справа. Без аргумента split() режет по пробелам и выбрасывает пустые куски, а splitlines() понимает \n и \r\n. partition всегда возвращает три элемента: если разделителя нет — (всё, "", ""). split("") запрещён — ValueError.

join вызывается у разделителя, а не у списка, и принимает только строки: один раз считает суммарную длину и копирует данные. Склейка s = s + chunk в цикле каждый раз создаёт новую строку: O(n²). Поэтому «собрать из кусков» — это список плюс join.

06Три сценария из практики

Нормализация email

ref_str_lab.pypython
def normalize_email(raw):
    return raw.strip().lower()

inbox = ["  Anna@Mail.RU ", "ivan@MAIL.RU", "  Anna@mail.ru"]
clean = [normalize_email(e) for e in inbox]
print(clean)
print(len(clean), len(set(clean)))
['anna@mail.ru', 'ivan@mail.ru', 'anna@mail.ru'] 3 2

Три адреса после strip().lower() схлопнулись в два: без нормализации «Anna@Mail.RU» и «Anna@mail.ru» считались бы разными людьми. Порядок важен: сначала срезать пробелы, потом менять регистр.

Строки отчёта собираются в список, а join склеивает их одним проходом: O(суммы длин) вместо O(n²) у + в цикле. Формат {name:8} дополняет имя до ширины 8, а {amount:>6,} прижимает сумму вправо и ставит запятую в тысячах.

07Пять ошибок, на которых спотыкаются

Ждать от строки изменяемости

s[0] = "Б" бросает TypeError: 'str' object does not support item assignment. s.upper() тоже не меняет s — он создаёт новую строку и возвращает её.

Собрать новую и присвоить: s = s.upper(), s = s.replace("б", "Б") или s[:i] + "Б" + s[i+1:].
Путать strip и removeprefix

"xxannaxx".strip("x") → "anna": это не префикс, а набор символов, который срезается с обоих концов. При этом "annaxx".removeprefix("xx") не меняет ничего — префикса "xx" там нет.

Нужен префикс или суффикс — removeprefix/removesuffix. Нужен набор символов на краях — strip.
split("") не работает

Пустой разделитель не имеет смысла: "abc".split("") → ValueError: empty separator. Это частая попытка «разрезать на символы» по аналогии с join.

На символы — list("abc"); по пробелам — "abc".split(); по разделителю — split(",").
str + int

"сумма: " + 1200 бросает TypeError: can only concatenate str (not "int") to str: Python не приводит типы неявно, в отличие от JavaScript.

f-string: f"сумма: {1200}" или явно "сумма: " + str(1200). Обратно — int(текст), но с try/except на битых данных.
O(n²) из-за + и in в цикле

s += chunk в цикле каждый раз копирует всё накопленное: O(n²) по времени. if word in big_text внутри цикла по словам тоже умножает O(n) на число итераций.

Копить куски в списке и один раз вызвать join; для повторных проверок — set или dict, а не in по длинному тексту.

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Почему s[0] = "X" падает и как всё-таки «изменить» строку?

Строка неизменяема: у типа нет операции присваивания по индексу, поэтому Python бросает TypeError. «Изменить» строку можно только собрав новую: s = s.replace("a", "A") или s = s[:i] + "X" + s[i+1:]. Старый объект при этом не меняется — другой код, держащий ссылку, видит прежнее значение.

Резюме: строка — значение, а не контейнер; правка создаёт новые бусы.
Чем strip("x") отличается от removeprefix("x")?

strip("x") снимает с обоих концов любые символы из набора "x" — сколько бы их ни было. removeprefix("x") снимает ровно одну подстроку "x" и только если строка с неё начинается.

"xxannaxx".strip("x") → "anna", "xxanna".removeprefix("x") → "xanna".

Резюме: strip — про набор символов на краях, removeprefix — про точный префикс.
Когда брать find, а когда index?

find возвращает -1, если подстроки нет, — это удобно, когда отсутствие нормально. index в той же ситуации бросает ValueError — берите его, когда подстрока обязана быть и падение лучше тихого -1. Если нужен только ответ «есть или нет» — sub in s.

Резюме: find — «где, если есть», index — «где, раз обязано быть».
Почему " ".join(parts) лучше, чем + в цикле?

Каждая s + chunk создаёт новую строку и копирует в неё всё накопленное: после n шагов скопировано 1 + 2 + … + n символов — O(n²). join заранее знает суммарную длину и копирует данные один раз — O(суммы длин). Ограничение: join принимает только строки, поэтому числа приводят через map(str, ...) или f-string.

Резюме: собрать список и склеить один раз — дешевле и читается лучше.
Зачем casefold, если есть lower?

lower меняет регистр, но не делает строки сравнимыми: "STRASSE".lower() == "straße".lower() → False. casefold выполняет агрессивное свёртывание (ß → ss), и сравнение даёт True. Для логинов, email и поиска по названиям — только casefold; для вывода он не годится.

Резюме: lower — для вида, casefold — для сравнения.

01 Дата из ISO

Превратите "2024-02-01" в "01.02.2024".

условиеpython
date = "2024-02-01"
# ожидается: 01.02.2024
Показать решение и разбор
решениеpython
date = "2024-02-01"
year, month, day = date.split("-")
print(".".join([day, month, year]))
01.02.2024

Что важно. split отдаёт три строки, распаковка даёт имена, join склеивает их в обратном порядке — без срезов и склеек +.

02 Отчёт из пар

Соберите отчёт по строкам «имя;сумма»: просуммируйте суммы по человеку и выведите по строке на каждого.

условиеpython
lines = ["Anna;1200", "Olga;1500", "Anna;500"]
# ожидается: суммы по пользователям, по строке на человека
Показать решение и разбор
решениеpython
lines = ["Anna;1200", "Olga;1500", "Anna;500"]
totals = {}
for line in lines:
    name, amount = line.split(";")
    totals[name] = totals.get(name, 0) + int(amount)
report = "\n".join(f"{name:<6}{amount:>8,}" for name, amount in totals.items())
print(report)
Anna 1,700 Olga 1,500

Что важно. split(";") даёт пару, int превращает сумму в число, словарь копит итоги, а join собирает строки. Складывать надо числа, а не строки — иначе суммы не сложились бы.

09Мостик: та же идея в pandas и SQL

pandas: аксессор .str

мост в pandaspython
import pandas as pd

df = pd.DataFrame({"email": ["  Anna@Mail.RU ", "ivan@MAIL.RU"]})
df["email"].str.strip().str.lower()       # та же нормализация, векторно
df["email"].str.contains("@")             # как in, но для каждой строки
df["email"].str.len()                     # как len()
df["email"].str.split("@", expand=True)   # split → две колонки

.str — это те же методы строк, применённые к каждой ячейке колонки. Пропуски NaN аксессор пропускает, поэтому вместо ручного цикла с strip().lower() пишут одну цепочку. Подробнее — в главе 18.

SQL: UPPER, TRIM, LIKE, REPLACE

мост в SQLsql
-- регистр и обрезка: как lower() и strip()
SELECT LOWER(TRIM(email)) FROM users;

-- поиск подстроки: как in и find
SELECT name FROM users WHERE name LIKE '%анна%';

-- в PostgreSQL регистр приводит ILIKE
SELECT name FROM users WHERE name ILIKE '%анна%';

-- сборка и длина: как join и len
SELECT UPPER(name) || ' <' || email || '>' AS label,
       LENGTH(TRIM(name)) AS name_len
FROM users;

-- замена подстроки: как replace
SELECT REPLACE(phone, ' ', '') FROM users;

SQL-функции делают то же, но на стороне базы: UPPER и LOWER — регистр, TRIM — края, LIKE — поиск по шаблону, || — склейка. LIKE в PostgreSQL регистрозависим, поэтому для «как casefold» нужен ILIKE. Подробнее — в главе 20.
