02Порядок выполнения: как база читает запрос

SQL пишут сверху вниз, а база выполняет в другом порядке. Из этого порядка растут почти все «почему не работает»: алиас, WHERE против HAVING, окно в WHERE.

ЭтапЧто происходитЧто важно
FROM / JOINстроится рабочее множество строккардинальность и NULL-ключи
WHEREфильтр строк до группировкиалиасы SELECT ещё не видны
GROUP BYстроки раскладываются по ключамNULL — отдельная группа
HAVINGфильтр групп после агрегатовагрегаты здесь разрешены
SELECTвычисляются выражения и алиасыоконные функции — здесь
DISTINCTубираются повторы результатапосле SELECT, до ORDER BY
ORDER BYсортировка результатавидит алиасы SELECT
LIMIT / OFFSETотрезаются строкибез ORDER BY порядок не определён

04Синтаксис-шаблон: весь запрос сразу

Порядок ключевых слов фиксирован, поэтому шаблон ниже — каркас: выкидывайте ненужные этапы, не меняя их местами.

шаблон.sqlsql
SELECT o.user_id,
       SUM(o.quantity * p.price) AS revenue
FROM orders o
JOIN products p ON p.id = o.product_id
WHERE o.created_at >= '2024-01-01'
GROUP BY o.user_id
HAVING SUM(o.quantity * p.price) > 5000
ORDER BY revenue DESC;
user_id | revenue ---------+---------- 1 | 76950.00 3 | 76500.00 2 | 23800.00 4 | 22000.00 (4 rows)

Заказ с user_id = NULL в результат не попал: ключ NULL — отдельная группа, и она не прошла HAVING. Об этом — страница 03.
