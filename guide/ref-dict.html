dict: шкаф с номерками Все методы словаря, безопасное чтение и порядок вставки

dict — основной способ сказать «найди по ключу за одно действие». Здесь — полная таблица методов, разница между get и setdefault, живые views и цена каждой операции.

⏱ 12 минут 🎯 уровень 1–2 🐍 Python 3.12 📚 глава 02

Типы справочника: вся карта · str · list · tuple · dict · set · frozenset · Counter · defaultdict · deque

Самое главное
  • Поиск по ключу — O(1) в среднем: hash(key) → ячейка → значение, а не перебор элементов.
  • Ключ обязан быть hashable: строка, число, tuple из hashable элементов. Список ключом быть не может.
  • Порядок — это порядок вставки, а не сортировки. Нужна сортировка — sorted(d) или sorted(d.items(), key=...).

01Что это и как устроено

Словарь хранит пары «ключ → значение» и даёт доступ по ключу за постоянное время. Ключи уникальны: повторная запись по существующему ключу заменяет значение, а не добавляет пару.

Внутри — хеш-таблица. Python считает hash(key), превращает его в номер ячейки и кладёт туда пару. При чтении номер вычисляется заново — поэтому не нужно перебирать остальные ключи. Если два ключа получили одну ячейку (коллизия), это штатная ситуация: пара кладётся рядом, и сравниваются один-два ключа, а не весь словарь.

Держите эту картинку в голове

Шкаф с номерками. У каждой вещи свой номерок — хеш. Вы не открываете все дверцы подряд, а сразу идёте к нужной. Записи при этом лежат в порядке, в котором их положили.

03Как создать

ref_dict_lab.pypython
prices = {"apple": 120, "pear": 90}            # литерал
empty = {}
pairs = dict([("a", 1), ("b", 2)])              # из пар
flags = dict.fromkeys(["read", "write"], False) # все ключи с одним значением
squares = {x: x * x for x in range(1, 4)}       # dict comprehension

print(prices, empty, pairs, flags, squares, sep="\n")
{'apple': 120, 'pear': 90} {} {'a': 1, 'b': 2} {'read': False, 'write': False} {1: 1, 2: 4, 3: 9}
Осторожно с fromkeys

Второе значение подставляется одно и то же во все ключи. Для изменяемого значения — dict.fromkeys(keys, []) — все ключи получат общий список. Стройте comprehension'ом: {k: [] for k in keys}.

05Разбор по группам

Все примеры страницы — в файле ref_dict_lab.py.

get: безопасное чтение

ref_dict_lab.pypython
prices = {"apple": 120, "pear": 90}
print(prices.get("apple"))
print(prices.get("plum"))
print(prices.get("plum", 0))
120 None 0

prices["plum"] бросил бы KeyError. get — для «а есть ли там что-нибудь?»: отсутствие ключа — нормальная ситуация, а не авария. Обратите внимание: get не создаёт ключ.

setdefault: положить, если нет

ref_dict_lab.pypython
d = {"a": 1}
print(d.setdefault("b", 0))     # создал ключ
print(d.setdefault("a", 999))   # не тронул существующий
print(d)
0 1 {'a': 1, 'b': 0}

setdefault возвращает существующее значение и создаёт новое только при отсутствии ключа. С ним группировка укладывается в одну строку: groups.setdefault(user, []).append(amount).

update, pop, popitem, del

ref_dict_lab.pypython
d = {"a": 1, "b": 2}
d.update({"b": 3, "c": 4})
print(d)
print(d.pop("c"))
print(d.pop("zzz", "нет"))
print(d.popitem())              # пара, вставленная последней
del d["a"]
print(d)
{'a': 1, 'b': 3, 'c': 4} 4 нет ('b', 3) {}

update не удаляет «лишние» ключи: пары, которых нет во втором словаре, остаются. popitem — LIFO, а не «случайная пара», как было в старых версиях.

keys, values, items — живые views

ref_dict_lab.pypython
prices = {"apple": 120, "pear": 90}
print(list(prices.keys()))
print(list(prices.values()))
print(list(prices.items()))

view = prices.keys()
prices["plum"] = 70
print(list(view))               # view живой
['apple', 'pear'] [120, 90] [('apple', 120), ('pear', 90)] ['apple', 'pear', 'plum']

keys, values, items не копируют данные: они смотрят на словарь и видят изменения. Для итерации с изменением словаря делайте список: for k in list(d):.

Порядок вставки и слияние

ref_dict_lab.pypython
d = {"b": 2, "a": 1}
d["c"] = 3
print(list(d))

base = {"a": 1, "b": 2}
extra = {"b": 20, "c": 30}
print(base | extra)
base |= {"d": 4}
print(base)
['b', 'a', 'c'] {'a': 1, 'b': 20, 'c': 30} {'a': 1, 'b': 2, 'd': 4}

Порядок — это порядок добавления ключей; перезапись значения позицию не меняет. | создаёт новый словарь, при совпадении ключей побеждает правый.

Копия, алиас и hashable

ref_dict_lab.pypython
a = {"x": 1}
alias = a
copy = a.copy()
alias["y"] = 2
copy["z"] = 3
print(a)
print(copy)

grid = {(10, 20): "start"}
print(grid[(10, 20)])
{'x': 1, 'y': 2} {'x': 1, 'z': 3} start

Ключом может быть только hashable объект: строка, число, tuple. Список, множество или словарь — нет. Кортеж с изменяемым элементом внутри — тоже нет: hash(tuple) считается по элементам.

06Три сценария из практики

Счётчик без магии

ref_dict_lab.pypython
words = ["sql", "python", "sql", "dbt"]
counts = {}
for w in words:
    counts[w] = counts.get(w, 0) + 1
print(counts)
{'sql': 2, 'python': 1, 'dbt': 1}

Это база, на которой построены Counter и defaultdict(int). Понимать её нужно, даже если в проде вы возьмёте готовый класс.

Группировка по ключу

ref_dict_lab.pypython
orders = [("Anna", 1200), ("Ivan", 800), ("Anna", 500)]
groups = {}
for user, amount in orders:
    groups.setdefault(user, []).append(amount)
print(groups)
{'Anna': [1200, 500], 'Ivan': [800]}

«Разложить — посчитать — собрать»: setdefault заменяет проверку if user not in groups. Ровно эту операцию делает defaultdict(list) и groupby в pandas.

Реестр обработчиков

ref_dict_lab.pypython
handlers = {"GET": "list_users", "POST": "create_user"}
print(handlers.get("DELETE"))
print(handlers.get("DELETE", "404"))
None 404

Вместо if/elif на десять веток — словарь «команда → обработчик» и .get() с запасным значением. Так устроены роутеры, фабрики и таблицы переходов.

07Пять ошибок, на которых спотыкаются

Обращение по отсутствующему ключу

d["missing"] бросает KeyError — типичная причина 500-х на неполном JSON.

Для «может не быть» — d.get(k, default) или if k in d.
Изменяемый ключ

d[[1, 2]] = "x" падает с TypeError: unhashable type: 'list'.

Ключ — строка, число, tuple из hashable элементов. Для своего класса — dataclass(frozen=True).
fromkeys с изменяемым значением

dict.fromkeys(keys, []) кладёт один и тот же список во все ключи: d["a"].append(1) меняет и d["b"].

Comprehension: {k: [] for k in keys} — новый объект на каждый ключ.
Изменение словаря во время итерации

Добавление или удаление ключа внутри for k in d: — RuntimeError: dictionary changed size during iteration.

Итерируйтесь по копии ключей: for k in list(d):, а изменения собирайте отдельно.
Ждать сортировки от порядка вставки

Словарь хранит порядок добавления. Если данные пришли в случайном порядке, вывод тоже будет случайным.

Нужен порядок — сортируйте явно: sorted(d), sorted(d.items(), key=...).

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем d[k] отличается от d.get(k)?

d[k] бросает KeyError, если ключа нет. d.get(k) возвращает None, а d.get(k, default) — указанное значение по умолчанию. Ни один из них не создаёт ключ.

Резюме: [] — «ключ обязан быть», get — «может не быть».
Почему список нельзя сделать ключом словаря?

Ключ обязан быть hashable: у объекта должен быть стабильный хеш и сравнение. Список изменяем — его содержимое можно поменять, а хеш «поехал» бы; поэтому Python запрещает list в ключах.

Tuple из неизменяемых элементов — можно: (10, 20).

Резюме: hashable = можно выдать стабильный номерок.
Гарантирован ли порядок ключей? Это сортировка?

Порядок гарантирован, но это порядок вставки, а не сортировки. Перезапись значения позицию не меняет, удаление и повторная вставка переносят ключ в конец.

Резюме: dict помнит, как вы клали; сортировать нужно явно.
Что такое keys(), values(), items() и почему их называют views?

Это лёгкие объекты-представления: они не копируют данные, а смотрят на словарь. Добавили ключ — он сразу виден в keys(). Нужен снимок — оберните в list().

Резюме: view — окно в словарь, а не фотография.
Чем pop(k) отличается от del d[k]?

pop(k) возвращает удалённое значение и умеет безопасный вариант pop(k, default). del d[k] ничего не возвращает и без ключа падает с KeyError.

Резюме: нужно значение — pop; нужен просто факт удаления — del.

01 Перевернуть словарь

Поменяйте местами ключи и значения. Если значения повторяются — побеждает последнее.

условиеpython
prices = {"apple": 120, "pear": 90}
# ожидается: {120: 'apple', 90: 'pear'}
Показать решение и разбор
решениеpython
inverse = {price: name for name, price in prices.items()}
print(inverse)
{120: 'apple', 90: 'pear'}

Что важно. items() даёт пары, comprehension меняет их местами. Значения становятся ключами — значит, должны быть hashable. Коллизии (одинаковые цены) перезаписывают друг друга: для «списка имён на цену» нужен defaultdict(list).

02 Сложить два дня

Есть два словаря «пользователь → число заказов». Сложите значения по общим ключам.

условиеpython
day1 = {"anna": 2, "ivan": 1}
day2 = {"anna": 1, "olga": 3}
# ожидается: {'anna': 3, 'ivan': 1, 'olga': 3}
Показать решение и разбор
решениеpython
total = {}
for day in (day1, day2):
    for user, n in day.items():
        total[user] = total.get(user, 0) + n
print(total)
{'anna': 3, 'ivan': 1, 'olga': 3}

Что важно. get(user, 0) решает проблему первого появления ключа. Через Counter это записывается короче (c1 + c2), но только для числовых частот.

09Мостик: та же идея в pandas и SQL

pandas: индекс как словарь меток

мост в pandaspython
import pandas as pd

s = pd.Series({"apple": 120, "pear": 90})   # dict → Series с индексом
s["apple"]                                   # доступ по метке
s.get("plum", 0)                             # аналог dict.get

Series — это «словарь метка → значение» плюс порядок и векторные операции. Строковый индекс ищет метку через хеш-таблицу, поэтому и здесь работает O(1) в среднем.

SQL: тот же поиск по ключу

мост в SQLsql
-- «найти по ключу»: B-tree индекс вместо перебора строк
SELECT * FROM users WHERE id = 42;

-- «соединить по ключу»: hash join строит таблицу, как dict
SELECT o.id, u.name
FROM orders o JOIN users u ON u.id = o.user_id;

Индекс в базе — это «оглавление»: база не читает всю таблицу, а идёт к нужной строке. А hash join буквально строит хеш-таблицу по ключу соединения — тот же dict, только внутри PostgreSQL.
