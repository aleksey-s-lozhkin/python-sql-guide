Типы справочника: вся карта · str · list · tuple · dict · set · frozenset · Counter · defaultdict · deque

Самое главное
  • deque — двусторонняя очередь: append, appendleft, pop, popleft — O(1), а индексация и insert в середине — O(n).
  • maxlen задаётся при создании: при переполнении append молча вытесняет элемент с другого конца. Это готовое скользящее окно.
  • У deque нет срезов, он не hashable и дороже по памяти; зато оба конца — полноценные «двери», в отличие от списка, где быстрый только правый край.

01Что это и как устроено

deque («deck») — упорядоченная последовательность, как список, но оптимизированная под два края. Добавить в начало, добавить в конец, снять с начала, снять с конца — все четыре операции стоят O(1). У списка операции с левым краем тянут на O(n): элементы лежат подряд, и вставка сдвигает весь массив.

Внутри CPython это не непрерывный массив, а связная структура из блоков. Поэтому левый край не «сдвигает» остальные элементы, а просто подцепляет новый блок. Обратная сторона: доступ по индексу в середине — O(n); срезов нет; deque не hashable; память на элемент больше, чем у списка.

🚪
Держите эту картинку в голове

Вагон с двумя дверями. Войти и выйти можно с любого конца, и обе двери работают одинаково быстро. У списка задняя дверь быстрая, а передняя — нет: чтобы поставить кого-то в начало, приходится пересаживать весь вагон.

Из того же ящика с инструментами главы 06: Counter считает, defaultdict группирует, а deque держит очередь. Подробный разбор метафоры — в главе 06.

Если оба конца не нужны — берите list: он проще, экономнее и умеет срезы. deque выигрывает только там, где важны две двери.

Все примеры страницы собраны в файле ref_deque_lab.py — его можно запустить и менять строки.

Оба конца: append, appendleft, pop, popleft

ref_deque_lab.pypython
q = deque([10, 20, 30])
q.appendleft(0)
q.append(40)
print(q)
print(q.popleft(), q.pop())

deque([0, 10, 20, 30, 40]) 0 40 deque([10, 20, 30])

Четыре операции — два готовых шаблона. Очередь: append + popleft — пришло справа, ушло слева, порядок FIFO. Стек: append + pop — пришло и ушло справа, порядок LIFO. Оба шаблона стоят O(1) на операцию.

extend и extendleft: направление важно

ref_deque_lab.pypython
left = deque([3, 4])
left.extend([5, 6])
right = deque([3, 4])
right.extendleft([1, 2])
print(left)
print(right)
deque([3, 4, 5, 6]) deque([2, 1, 3, 4])

extendleft идёт по итерируемому слева направо и каждый элемент кладёт в левый конец. Первый элемент оказывается дальше всех от края, поэтому итоговый порядок обратный. Это не баг, а следствие «двери»: extendleft([1, 2]) делает то же, что два appendleft подряд.

rotate: прокрутка

ref_deque_lab.pypython
q = deque([1, 2, 3, 4, 5])
q.rotate(2)
print(q)
q.rotate(-2)
print(q)
deque([4, 5, 1, 2, 3]) deque([1, 2, 3, 4, 5])

rotate(2) сдвигает всё вправо на два шага: правые элементы переезжают в начало. rotate(-2) — влево, возвращает как было. rotate(len(q)) не меняет ничего. Метод возвращает None и крутит deque на месте.

maxlen: окно, которое само себя чистит

recent = deque(maxlen=3)
for value in [10, 20, 30, 40]:

Как только длина упирается в maxlen, каждый append вытесняет самый левый элемент, а appendleft — самый правый. Следить за размером и вручную вызывать popleft не нужно. Одна тонкость: insert при полном окне не вытесняет, а бросает IndexError — поведение у методов разное.

copy() — поверхностная копия, как у списка: вложенные списки и словари остаются общими. reverse() разворачивает на месте и возвращает None; нужен итератор — reversed(q). clear() освобождает все блоки.

Чего у deque нет: срезы и hash

ref_deque_lab.pypython
q = deque([1, 2, 3])

    print(q[1:3])

    print("срез:", error)

    print(hash(q))

    print("hash:", error)

Два ограничения сразу: срезов нет, потому что кусок deque — это не непрерывный массив; hash нет, потому что deque изменяемый. Хотите кусок — list(q)[1:3] создаст копию; без копии всего deque — itertools.islice(q, 1, 3) (ленивый итератор, но до нужного места он всё равно дойдёт перебором). Нужен hashable-снимок — tuple(q), если элементы сами hashable.

06Три сценария из практики

Очередь задач: FIFO

ref_deque_lab.pypython
tasks = deque(["заказ #101", "заказ #102", "заказ #103"])
tasks.append("заказ #104")
while tasks:
    print("обработан:", tasks.popleft())
обработан: заказ #101 обработан: заказ #102 обработан: заказ #103 обработан: заказ #104

Классическая очередь: новые задачи добавляются справа, обработчик забирает слева. На списке тот же код через pop(0) был бы O(n²) на всю очередь. Нужен стек — тот же deque, только pop() вместо popleft(); для стека подойдёт и list (справочник по list).

Обход в ширину (BFS)

ref_deque_lab.pypython
graph = {
    "Anna": ["Ivan", "Olga"],
    "Ivan": ["Olga"],
    "Olga": ["Petr"],
    "Petr": [],
}


def bfs(start):
    queue = deque([start])
    seen = {start}
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph.get(node, []):
            if nxt not in seen:
                seen.add(nxt)
                queue.append(nxt)
    return order


print(bfs("Anna"))
['Anna', 'Ivan', 'Olga', 'Petr']

BFS — это очередь по определению: соседи текущего узла встают в конец, а следующий узел берётся из начала. Помечать seen нужно в момент постановки в очередь, иначе узел попадёт туда дважды. С deque каждая операция O(1), со списком pop(0) обход стал бы O(V²).

Скользящее окно и rate limiter

ref_deque_lab.pypython
prices = [1200, 800, 1500, 900, 1100]
window = deque(maxlen=3)
for price in prices:
    window.append(price)
    print(list(window), "→", round(sum(window) / len(window), 2))
[1200] → 1200.0 [1200, 800] → 1000.0 [1200, 800, 1500] → 1166.67 [800, 1500, 900] → 1066.67 [1500, 900, 1100] → 1166.67

maxlen=3 — это и есть окно: старый чек уходит сам, когда приходит новый. Здесь среднее каждый раз считается заново (sum по окну, O(k)); если окно большое, поддерживают бегущую сумму и вычитают вытесненный элемент.

ref_deque_lab.pypython
class RateLimiter:
    def __init__(self, limit, window):
        self.limit = limit
        self.window = window
        self.hits = deque()

    def allow(self, now):
        while self.hits and now - self.hits[0] >= self.window:
            self.hits.popleft()
        if len(self.hits) >= self.limit:
            return False
        self.hits.append(now)
        return True


limiter = RateLimiter(limit=2, window=10)
for moment in [0, 1, 2, 9, 10, 11]:
    print(moment, limiter.allow(moment))
0 True 1 True 2 False 9 False 10 True 11 True

Ограничитель запросов: в deque хранятся моменты последних обращений. Старые вычищаются через popleft, пока не выйдут из окна; если в окне уже limit обращений — отказ. Каждый вызов амортизированно O(1). В лаборатории момент передаётся аргументом, чтобы вывод не зависел от машины; в реальном коде на этом месте стоит time.monotonic().

07Пять ошибок, на которых спотыкаются

Ждать от extendleft прежнего порядка

deque([3, 4]).extendleft([1, 2]) даёт deque([2, 1, 3, 4]), а не [1, 2, 3, 4]: каждый элемент кладётся в левый конец и выталкивает предыдущий вправо.

Нужен прямой порядок — добавьте по одному в обратном порядке: q.appendleft(2), затем q.appendleft(1). Или соберите список и разверните его через reversed.
Индексировать середину в цикле

for i in range(len(q)): q[i] и insert в середину — это O(n) на операцию и O(n²) на цикл. deque быстрый только у краёв.

Работайте через append/popleft; если нужен произвольный доступ — list.
maxlen молча выбрасывает данные

deque(history, maxlen=10) оставит только последние десять элементов — без предупреждения. При переполнении append вытесняет край, а insert вообще бросает IndexError: поведение разное.

Это допустимо, только если окно — часть замысла. Нужна полная история — list; нужна проверка — сравните len(q) с maxlen до вставки.
Пытаться срезать deque

q[1:3] бросает TypeError: срезов у deque нет, есть только индексация. Код, перенесённый со списка, падает на первом же срезе.

Копия куска — list(q)[1:3] или itertools.islice(q, 1, 3).
Класть deque в set или в ключ словаря

hash(deque(...)) — TypeError: unhashable type. deque изменяемый, поэтому не может быть ключом.

Снимок для ключа — tuple(q), если элементы hashable. Либо храните индекс и не делайте deque ключом.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Чем deque отличается от list?

deque оптимизирован под оба конца: appendleft/popleft — O(1), у списка вставка и удаление в начале — O(n). Зато у списка доступ по индексу O(1) и есть срезы, а у deque индексация в середине O(n), срезов нет, и он не hashable.

Резюме: очередь с двумя дверями против массива с индексами.
Что делает rotate(1) и rotate(-1)?

rotate(1) сдвигает все элементы на шаг вправо: последний переезжает в начало. rotate(-1) — на шаг влево: первый уходит в конец. Возвращается None, deque меняется на месте.

Резюме: положительное n — вправо, отрицательное — влево.
Что происходит при добавлении в полный deque с maxlen?

append добавляет справа и вытесняет левый элемент, appendleft — наоборот. Длина остаётся равной maxlen. Исключение — insert: при полном окне он бросает IndexError.

Резюме: окно фиксированного размера, старые данные уходят сами.
Как взять «кусок» deque, если срезов нет?

Скопировать в список: list(q)[1:3] — просто, но копирует весь deque. Без копии всего deque — itertools.islice(q, 1, 3), ленивый итератор.

Резюме: срез делается через list или islice, не через q[1:3].
Почему deque нельзя положить в set?

Потому что deque изменяемый и не hashable: его хеш менялся бы при каждом append, и множество сломалось бы. Для ключа нужен неизменяемый снимок — tuple(q).

Резюме: изменяемое — не ключ; сначала снимок.

01 Палиндром

Проверьте, читается ли строка одинаково в обе стороны. Регистр и пробелы не важны.

условиеpython
print(is_palindrome("А роза упала на лапу Азора"))
print(is_palindrome("python"))
# ожидается: True, затем False
Показать решение и разбор
решениеpython
def is_palindrome(text):
    chars = deque(ch for ch in text.lower() if ch.isalnum())
    while len(chars) > 1:
        if chars.popleft() != chars.pop():
            return False
    return True


print(is_palindrome("А роза упала на лапу Азора"))
print(is_palindrome("python"))
True False

Что важно. Сравниваем две двери: левый символ с правым. deque здесь идеален, потому что оба конца снимаются за O(1), а середина не нужна вовсе. Пустая строка и строка из одного символа — палиндромы: цикл просто не выполняется.

02 Скользящее среднее

Посчитайте среднее по окну из трёх последних значений для каждого шага.

условиеpython
values = [1200, 800, 1500, 900, 1100]
# ожидается: [1166.67, 1066.67, 1166.67]
Показать решение и разбор
решениеpython
def moving_average(values, size):
    window = deque(maxlen=size)
    result = []
    for value in values:
        window.append(value)
        if len(window) == size:
            result.append(round(sum(window) / size, 2))
    return result


print(moving_average([1200, 800, 1500, 900, 1100], 3))
[1166.67, 1066.67, 1166.67]

Что важно. maxlen=size сам вытесняет старый элемент, ручной popleft не нужен. Среднее считается за O(size) на шаг; на большом окне поддерживают бегущую сумму и вычитают выбывший элемент — тогда O(1) на шаг.

09Мостик: та же идея в pandas и SQL

Прямого аналога deque в pandas и SQL нет: у таблицы нет двух концов, к которым «двери» открываются за O(1). Но три идеи переносятся один в один — скользящее окно, «последние N» и буфер в памяти сервиса.

pandas: окно вместо maxlen

мост в pandaspython
import pandas as pd

s = pd.Series([1200, 800, 1500, 900, 1100])
s.rolling(3).mean()     # окно из трёх последних — как deque(maxlen=3)
s.shift(1)              # «предыдущее значение» вместо popleft
s.diff()                # разница с предыдущим — вытесненный и новый

rolling(3) — то же скользящее окно, только векторно и с обработкой краёв: первые строки получат NaN, потому что окна ещё нет. В deque вы бы просто ждали, пока len(window) достигнет размера.

SQL: LIMIT и «последние N»

мост в SQLsql
-- последние 5 событий: то же окно, но на стороне базы
SELECT *
FROM events
ORDER BY created_at DESC
LIMIT 5;

-- окно по строкам задаётся ROW_NUMBER, а не размером буфера
SELECT * FROM (
  SELECT *, ROW_NUMBER() OVER (ORDER BY created_at DESC) AS rn
  FROM events
) t
WHERE rn <= 5;

LIMIT отрезает строки после ORDER BY: без сортировки это «первые попавшиеся N», а не «последние». База не держит кольцевой буфер между запросами — окно каждый раз строится заново, поэтому для «последних N» нужен правильный порядок и подходящий индекс.

Backend: буфер последних событий

buffers.pypython
from collections import deque


class LastEvents:
    def __init__(self, size=100):
        self.events = deque(maxlen=size)

    def add(self, event):
        self.events.append(event)


last = LastEvents(3)
for event in ["login", "buy", "logout", "buy"]:
    last.add(event)
print(list(last.events))
['buy', 'logout', 'buy']

В сервисах так хранят последние N логов, метрик или запросов: буфер не растёт, старые записи исчезают сами, а память ограничена maxlen. deque здесь — не «структура данных из учебника», а рабочий инструмент backend-разработчика.
