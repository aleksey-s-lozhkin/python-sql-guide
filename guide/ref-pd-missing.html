Пропуски: NaN, None и pd.NA Дырка в таблице — это факт, а не ноль

Пропуск — это не значение: его нельзя сравнивать, с ним нельзя считать, но можно заметить, удалить, заполнить или сохранить флагом. Здесь — что делает каждая операция и где ловушка.

Самое главное
  • Пропуск бывает трёх видов: NaN, None (в колонке становится NaN) и pd.NA. Ловить все три нужно через isna().
  • dropna, fillna, ffill возвращают новый объект: без присваивания таблица не меняется (Copy-on-Write).
  • Колонка с NaN — float64; fillna(0) её не исправит. Для целых — Int64.

01Что это и как устроено

Пропуск — это отсутствие значения, а не ноль. Носителей несколько: np.nan (float, не равный себе), None (в колонке становится NaN) и pd.NA (nullable-типы). Снаружи их не различить — isna() узнаёт все три.

В pandas 3.0 текст получает dtype str (не object), пропуск в нём печатается как NaN, а числовая колонка с одним NaN становится float64. Плюс включён Copy-on-Write: операции возвращают копию и исходную таблицу не меняют.

Держите эту картинку в голове

Пропуск — дырка в таблице. Дырку можно закрыть (заполнить), признать и обойти (удалить строку), можно оставить и отметить флагом.

Но нельзя считать дырку нулём по умолчанию: средняя зарплата по отделу не станет ниже оттого, что у одного сотрудника данных нет. Метафору целиком разбирает глава 17.

07Пять ошибок, на которых спотыкаются

fillna(0) не даёт int

Колонка с NaN уже float64: fillna(0) заменяет пропуски, но dtype не меняет.

Сначала astype("Int64") или convert_dtypes(). И спросите, правда ли ноль — правильное значение.
dropna() по умолчанию — any

Без параметров удаляется строка, у которой пропуск в любой колонке, — на широкой таблице можно потерять почти всё.

subset=[...] для нужных колонок, how="all" для полных пустышек, thresh для порога.
Сравнение с NaN

df[df["amount"] == np.nan] всегда пуст: NaN не равен даже себе, а с pd.NA сравнение вернёт pd.NA.

Маска — df["amount"].isna(); для «не пропуск» — notna().
NaN-ключ в merge

pandas соединяет NaN с NaN, а SQL NULL с NULL — нет: join размножит строки, а вы будете ждать пустого результата.

Перед join решите судьбу пропусков: dropna(subset=[key]), fillna("неизвестно") или indicator=True и проверка результата.
fillna без присваивания

df.fillna(0) возвращает новую таблицу: запись без присваивания ничего не меняет — в pandas 3.0 это Copy-on-Write.

df["amount"] = df["amount"].fillna(0) или df = df.fillna(0). inplace=True работает, но в 3.0 не рекомендуется.

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем NaN отличается от None и pd.NA?

NaN — float «не число», None — объект (в колонке становится NaN), pd.NA — единый пропуск nullable-типов. Проверять всё равно через isna().

Резюме: разные носители, один смысл — «значения нет».
Почему целая колонка с NaN стала float64 и как вернуть целые?

NaN — float, поэтому колонка приводится к float64, а fillna(0) dtype не меняет. Nullable Int64 хранит и целые, и pd.NA; convert_dtypes() подбирает его сам.

Резюме: «целое с пропуском» — это Int64, а не float64 после fillna(0).
Чем dropna(how="any") отличается от thresh?

how="any" — порог «ноль пропусков»: строка остаётся, только если заполнены все колонки из subset. thresh=k — порог «k непустых значений» в любых колонках.

Резюме: any смотрит на пропуски, thresh — на заполненные ячейки.
Что делает ffill и почему без sort_values он врёт?

ffill() копирует последнее известное значение вниз по строкам: «последнее» — предыдущая строка таблицы, а не предыдущая по времени. На несортированных данных это значение из будущего, поэтому сначала sort_values.

Резюме: ffill — про порядок строк, а не про время; сортируйте сами.
Почему df[df["amount"] == np.nan] всегда пустой?

По определению NaN != NaN, поэтому сравнение с np.nan даёт False; у nullable-значений pd.NA == pd.NA возвращает pd.NA.

Резюме: пропуск ищут маской isna(), а не равенством.

09Мостик: NULL и COALESCE в SQL

Прямые соответствия

мост в SQLsql
-- пропуски: как isna()
SELECT * FROM orders WHERE amount IS NULL;

-- count против size: COUNT(*) — строки, COUNT(col) — непустые значения
SELECT COUNT(*) AS rows, COUNT(amount) AS known FROM orders;

-- заполнение: как fillna(0), среднее: как skipna=True
SELECT COALESCE(amount, 0) AS amount FROM orders;
SELECT AVG(amount) FROM orders;

-- NaN-ключ в merge: в SQL NULL с NULL не соединяется
SELECT a.city, a.orders, b.manager
FROM a JOIN b ON a.city = b.city;

В SQL NULL — состояние, а не значение: NULL = NULL даёт UNKNOWN, поэтому join по пропущенному ключу ничего не найдёт. В pandas NaN при merge совпадает сам с собой — отсюда разные результаты.

COUNT(*) — по строкам, COUNT(col) — по непустым значениям: это len(df) против df.count(). COALESCE — тот же fillna, но в базе.
