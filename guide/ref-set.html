set отвечает на вопрос «есть или нет» за одно действие — и не обещает порядка. Здесь полный список методов, разница между &, |, - и ^, frozenset для ключей и пять ловушек, которые встречаются в проде.

Типы справочника: вся карта · list · tuple · dict · set · Counter · defaultdict · deque

Самое главное
  • set — набор уникальных hashable элементов: повтор не добавляется, порядок не гарантирован, индексов и срезов нет.
  • Проверка входа и добавление — O(1) в среднем. Четыре операции (&, |, -, ^) стоят O(размера наборов), а не O(n·m).
  • Нужны порядок и индексы — list; пары «ключ → значение» — dict; неизменяемый набор для ключа — frozenset.

01Что это и как устроено

Множество хранит набор объектов без повторов: повторное добавление ничего не меняет. Порядка нет — это не журнал с номерами, а картотека, где важен только факт «внутри или нет». Поэтому у set нет индексов, срезов и доступа «по позиции».

Внутри — та же хеш-таблица, что у словаря, но без значений: hash(x) даёт номер ячейки, при коллизии — сравнение и пробирование. Отсюда три свойства: элементы обязаны быть hashable; проверка x in s — O(1) в среднем; порядок обхода зависит от хешей и не гарантирован. Плата — память: таблица резервирует пустые ячейки (216 байт против 88 у списка из трёх чисел).

Для строк хеш к тому же рандомизирован между запусками — это защита от подбора коллизий. Поэтому вывод множества строк нельзя сравнивать с эталонным списком. Подробнее — в главе 04.

🛂
Держите эту картинку в голове

Фейс-контроль. set — это список гостей на входе в клуб. Охранник не обходит зал в поисках человека: он смотрит в список — «есть уже?» — и решает за одно действие. Второй раз одного и того же не записывают, а порядок гостей в картотеке никого не интересует.

Метафора объясняет три свойства сразу: проверка входа O(1), дубликатов не бывает, порядка нет. Метафору целиком разбирает глава 04.

05Разбор по группам

Все примеры страницы — в файле ref_set_lab.py. Множества строк печатаются через sorted, иначе вывод менялся бы от запуска к запуску.

add, remove, discard

remove — «элемент обязан быть»: его отсутствие это ошибка. discard — «удали, если есть». Проверка x in s перед удалением тоже стоит O(1), так что выбор — про намерение, а не про скорость.

pop и clear

ref_set_lab.pypython

В отличие от list.pop(), у множества нет «последнего» элемента: pop снимает произвольный. На пустом множестве он бросит KeyError. Для «взять любой элемент» без изменения набора есть next(iter(s)).

update

update — это |=: дописывает элементы второго набора и игнорирует дубли. Возвращает None, потому что меняет множество на месте.

update("abc") против add("abc")

ref_set_lab.pypython
s = set()
s.update("abc")                  # строка — итерируемое: добавляются буквы

Строка — итерируемый объект из символов. update разбирает её на элементы, а add кладёт один объект. Это же различие объясняет, почему update({"ab"}) и update("ab") дают разный результат.

Четыре операции

ref_set_lab.pypython
a = {"python", "sql", "pandas"}
b = {"python", "dbt", "sql"}

print(sorted(a.union(b)))
print(sorted(a.intersection(b)))
print(sorted(a.difference(b)))
print(sorted(a.symmetric_difference(b)))
['dbt', 'pandas', 'python', 'sql'] ['python', 'sql'] ['pandas'] ['dbt', 'pandas']

union — «хоть где-то», intersection — «и там, и там», difference — «только здесь», symmetric_difference — «ровно в одном». Методы не меняют исходные наборы и возвращают новый.

*_update на месте

ref_set_lab.pypython
a = {"python", "sql", "pandas"}
b = {"python", "dbt"}

c = a.copy()
c.intersection_update(b)
print(sorted(c))

d = a.copy()
d.difference_update(b)
print(sorted(d))

e = a.copy()
e.symmetric_difference_update(b)
print(sorted(e))
['python'] ['pandas', 'sql'] ['dbt', 'pandas', 'sql']

Версии с _update меняют множество на месте и возвращают None — как list.sort(). На больших наборах это экономит память, но требует быть внимательным: исходные данные уже не те.

Операторы и отношения

Операторы &, |, -, ^ — те же четыре операции, только компактнее. <= — «подмножество» (нестрогое), < — строгое: набор меньше и не равен. Методы issubset, issuperset, isdisjoint делают то же и принимают любой итерируемый объект.

frozenset

ref_set_lab.pypython
fs = frozenset({"read", "write"})
print(sorted(fs))

roles = {
    frozenset({"read", "write"}): "editor",
    frozenset({"read"}): "viewer",
}
print(roles[frozenset({"write", "read"})])   # порядок элементов не важен

try:
    fs.add("delete")             # frozenset неизменяем
except AttributeError as e:
    print(type(e).__name__)

print(fs <= frozenset({"read", "write", "delete"}))
['read', 'write'] editor AttributeError True

frozenset — запечатанная картотека: те же операции, но нет add и remove, зато есть хеш. Поэтому его можно класть в ключ словаря и в элемент другого множества. Набор прав, frozenset({"read", "write"}), — естественный идентификатор роли.

Четыре операции отвечают на четыре разных вопроса: что общего, что только у первого, что только у второго, нет ли пересечения вовсе. В pandas это Index.intersection и Index.difference, в SQL — INTERSECT и EXCEPT.

Участники — это множество: объединение даёт полный список, разность — новичков. А набор прав — frozenset: неизменяемый, поэтому годится в ключ словаря-кэша. Обратите внимание: frozenset({"write", "read"}) находит ту же роль, что и frozenset({"read", "write"}) — порядок не важен.

07Пять ошибок, на которых спотыкаются

{} — это dict

{} создаёт пустой словарь, а не пустое множество. Код, который ждёт set, получает dict — и падает на первом же add.

Пустое множество — set(); проверить тип — type(x).__name__.
remove вместо discard

remove(x) бросает KeyError, если элемента нет. Для «удали, если есть» это лишняя авария, особенно на данных из внешнего источника.

Отсутствие элемента — норма: discard(x) или if x in s: s.remove(x).
Ставка на порядок множества

Порядок обхода зависит от хешей, а для строк рандомизирован между запусками. list(s) в тесте будет падать через раз, а вывод — меняться.

Для печати — sorted(s); сравнивайте наборы как наборы: set(result) == {"a", "b"}.
Нехешируемый элемент

{["a"]} и s.add({"k": 1}) падают с TypeError: unhashable type: множество принимает только hashable.

Кортеж вместо списка ({("a",)}), frozenset вместо множества или строка как сериализованный ключ.
update("abc") добавляет буквы

Строка итерируема по символам, поэтому update("abc") добавляет три элемента 'a', 'b', 'c', а не одну строку "abc".

Один элемент — add("abc"); несколько — update(["abc", "def"]).

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем set отличается от list?

Список хранит элементы по порядку и разрешает дубликаты; множество хранит только уникальные и порядка не обещает. Внутри множества — хеш-таблица, поэтому проверка входа O(1) в среднем против O(n) у списка.

Ограничение: цена — память и потеря индексов: s[0] и срез не работают.

Резюме: list — про порядок, set — про «есть или нет».
Чем set отличается от dict, если внутри у обоих хеш-таблица?

У словаря есть значения и сохраняется порядок вставки. У множества только ключи, и порядок не гарантирован. set — это словарь, у которого значение не нужно.

Резюме: set = dict без значений и без обещания порядка.
Почему порядок элементов не гарантирован?

Элементы лежат в ячейках, вычисленных из хеша; обход идёт по ячейкам, а не по истории вставки. Для строк хеш рандомизирован между запусками — поэтому порядок может отличаться даже у двух запусков одной программы.

Резюме: порядок — следствие хешей, а не порядка добавления.
Что можно класть в set?

Только hashable: числа, строки, tuple из hashable элементов, frozenset. Списки, словари и обычные множества — нельзя. Правило то же, что для ключей словаря.

Резюме: hashable = можно выдать стабильный номерок.
Что такое frozenset и зачем он нужен?

Неизменяемое множество. Оно hashable, поэтому может быть ключом словаря или элементом другого множества. Нужен, когда набор значений — это идентификатор: права доступа, набор тегов, ключ кэша.

Резюме: запечатанная картотека, которую можно повесить на вешалку dict.

01 Что изменилось за два дня

Даны два списка пользователей за соседние дни. Найдите тех, кто был ровно в одном из дней: и новых, и ушедших.

условиеpython
day1 = ["Anna", "Ivan", "Olga"]
day2 = ["Ivan", "Petr"]
# ожидается: ['Anna', 'Olga', 'Petr']
Показать решение и разбор
решениеpython
day1 = ["Anna", "Ivan", "Olga"]
day2 = ["Ivan", "Petr"]

only_one_day = set(day1) ^ set(day2)
print(sorted(only_one_day))
['Anna', 'Olga', 'Petr']

Что важно. Симметричная разность — это «ровно в одном из двух». (day1 - day2) | (day2 - day1) дало бы то же самое, но длиннее. Для печати нужен sorted: порядок множества не определён.

02 Кэш ролей по набору прав

Сделайте функцию, которая по набору прав возвращает роль и кэширует результат. Наборы прав должны быть ключами кэша.

условиеpython
# роль: {"read", "write"} → admin, {"read"} → viewer
# повторный вызов не должен создавать новую запись в кэше
Показать решение и разбор
решениеpython
cache = {}

def role(perms):
    key = frozenset(perms)
    if key not in cache:
        cache[key] = "admin" if "write" in key else "viewer"
    return cache[key]

print(role({"read", "write"}))
print(role({"read"}))
print(role({"read", "write"}))   # уже из кэша
print(len(cache))
admin viewer admin 2

Что важно. Обычное множество изменяемо и ключом быть не может — frozenset решает проблему. Два разных набора дали две записи, а повторный вызов попал в кэш: len(cache) равен 2, а не 3.

09Мостик: та же идея в pandas и SQL

pandas: unique и isin

мост в pandaspython
import pandas as pd

df = pd.DataFrame({"user": ["Anna", "Ivan", "Anna"], "amount": [1200, 800, 500]})

df["user"].unique()                    # как set, но массив
df["user"].isin({"Anna", "Petr"})      # как `in set` для каждой строки

SQL: IN, EXISTS и операции над результатами

мост в SQLsql
-- проверка входа: как `x in s`
SELECT * FROM users WHERE id IN (1, 2, 3);

-- то же через EXISTS
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM blocked b WHERE b.user_id = u.id);

-- уникальность: DISTINCT
SELECT DISTINCT user_id FROM orders;

-- операции над наборами строк
SELECT user_id FROM a UNION     SELECT user_id FROM b;   -- объединение
SELECT user_id FROM a INTERSECT SELECT user_id FROM b;   -- пересечение
SELECT user_id FROM a EXCEPT    SELECT user_id FROM b;   -- разность

UNION неявно делает DISTINCT — то есть строит множество и платит за это; UNION ALL дешевле, если дубли допустимы. IN и EXISTS — это «есть или нет» на языке SQL, а DISTINCT — та же дедупликация.
