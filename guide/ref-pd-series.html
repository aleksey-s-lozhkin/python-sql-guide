Самое главное
  • Series — колонка с подписями: значения + индекс + имя; DataFrame — набор колонок с общим индексом, dtype у каждой свой.
  • df["a"] — Series, df[["a"]] — DataFrame; assign/rename/drop возвращают новую таблицу, df["c"] = ... меняет текущую.
  • В pandas 3.0 строки — dtype str, Copy-on-Write всегда: .copy() независим, цепочка df["a"][0] = ... исходник не меняет.

01Что это и как устроено

У pandas два объекта. Series — одномерная колонка: значения, индекс подписей и имя. DataFrame — набор колонок с общим индексом; колонка таблицы — это Series с тем же индексом, а df["amount"] * 1.2 считается векторно, без цикла.

В pandas 3.0 строки получают dtype str, а не object, и Copy-on-Write включён всегда: df.copy() независима, цепочка df["a"][0] = ... таблицу не меняет.

📖
Держите эту картинку в голове

DataFrame — это таблица с оглавлением. Колонки — разделы, а индекс — подписи строк: по ним находят нужную строку, не пересчитывая позиции.

Series — одна страница той же книги. У неё те же подписи (индекс), но значения только из одной колонки, поэтому Series — не «просто список», а список с оглавлением. Подробный разбор метафоры — в главе 12.

03Как создать

Series собирается из списка, словаря или скаляра: список даёт индекс 0, 1, 2, словарь — порядок ключей, скаляр растягивается по заданному индексу.

ref_pd_series_lab.pypython
s = pd.Series([1200, 800, 500], index=["anna", "ivan", "olga"], name="amount")
print(s)
print(s.index.tolist(), s.dtype, s.name)
print(s.values, s.to_numpy())
print(s["anna"], s.iloc[0], s.loc["ivan"])   # метка, позиция, метка — кратко

by_dict = pd.Series({"anna": 1200, "ivan": 800, "olga": 500})
print(by_dict.index.tolist())          # порядок ключей сохранён
print(pd.Series(7, index=["a", "b", "c"]).tolist())
anna 1200 ivan 800 olga 500 Name: amount, dtype: int64 ['anna', 'ivan', 'olga'] int64 amount [1200 800 500] [1200 800 500] 1200 1200 800 ['anna', 'ivan', 'olga'] [7, 7, 7]

s["anna"], s.iloc[0] и s.loc["ivan"] дают одно число (подробно — страница 02); словарь сохраняет порядок ключей.

DataFrame — из словаря колонок одной длины, списка словарей (словарь = строка) или CSV-строки через read_csv и io.StringIO.

Страница снята в pandas 3.0.1: в 2.x строки были object, а Copy-on-Write включали отдельно.

Copy-on-Write: копия, view и chained assignment

ref_pd_series_lab.pypython
df = pd.DataFrame({"user": ["anna", "ivan"], "amount": [1200, 800]})
df["amount"][0] = 999            # так делать нельзя: в pandas 3 только предупредит
print(df["amount"].tolist())     # [1200, 800] — исходник не изменился
df2 = df.copy()                  # CoW: независимая копия
df2["amount"] = df2["amount"] * 2
print(df["amount"].tolist(), df2["amount"].tolist())
col = df["amount"]
df["amount"] = [1500, 900]
print(col.tolist())              # [1200, 800] — колонка не «увидела» правку
s1 = pd.Series([1200, 800], index=["anna", "ivan"])
s2 = pd.Series([100, 50], index=["ivan", "olga"])
print(s1 + s2)
[1200, 800] [1200, 800] [2400, 1600] [1200, 800] anna NaN ivan 900.0 olga NaN dtype: float64

Copy-on-Write включён всегда: цепочка df["amount"][0] = 999 не меняет таблицу, а печатает ChainedAssignmentError. Арифметика выравнивает Series по меткам: у несовпадающих появляется NaN — спасает s1.add(s2, fill_value=0).

NaN и dtype колонки

ref_pd_series_lab.pypython
df = pd.DataFrame({"amount": [1200, None, 500]})
print(df)
print(df["amount"].dtype)                       # float64: NaN не влез в int64

None в целочисленной колонке превращает её в float64: целые становятся 1200.0. Nullable Int64 сохраняет целые, а пропуск оставляет <NA>.

07Пять ошибок, на которых спотыкаются

Путать df["a"] и df[["a"]]

df["a"] — Series, df[["a"]] — DataFrame: shape (3,) против (3, 1), и операции дальше разные.

Расчёт — по Series, таблица формы — по df[["a"]].
Присваивать в цепочку

df["amount"][0] = 999 пишет во временную Series: в pandas 3.0 это только предупреждение ChainedAssignmentError, а таблица остаётся [1200, 800].

df.loc[0, "amount"] = 999 или df["amount"] = ... для всей колонки.
Искать значения через in по DataFrame

"amount" in df → True (колонка), а "anna" in df → False: проверяются имена колонок, а не ячейки.

Значения — df["user"].isin(["anna"]).any().
Складывать Series с разными индексами

s1 + s2 выравнивается по меткам: у anna и olga метка есть только в одной Series, поэтому там NaN.

Свести индексы: s1.add(s2, fill_value=0) или reindex.
Забыть, что NaN меняет dtype

pd.DataFrame({"amount": [1200, None, 500]}) даёт float64: целые стали 1200.0, проверка «колонка целая» ломается.

Nullable Int64: df["amount"].astype("Int64") — пропуск остаётся <NA>.

08Мини-проверка

Пять вопросов на понимание и две задачи. Сначала своя попытка — потом спойлер.

Чем Series отличается от DataFrame?

Series — одномерный объект: индекс, значения, имя. DataFrame — набор Series с общим индексом и именами колонок, dtype у каждой свой. Ограничение: Series не знает о соседних колонках, а таблица не однородна.

Резюме: колонка с оглавлением против таблицы.
Что такое индекс и почему он не равен номеру строки?

Индекс — подписи строк, а не позиции: сортировка и фильтрация метки сохраняют. loc ищет по метке, iloc — по позиции. Ограничение: метка может повторяться и вернуть несколько строк.

Резюме: метка живёт дольше позиции.
Чем df["a"] отличается от df[["a"]] и когда какой брать?

Одинарные скобки — Series, двойные — DataFrame: shape (3,) против (3, 1). Для вычислений удобнее Series, для формы — DataFrame. Ограничение: присваивание в df[["a"]] исходник не меняет — CoW.

Резюме: одни скобки — вектор, двойные — таблица.
Почему в pandas 3 строки — это str, а не object?

Строковые колонки получают dtype str — это видно в dtypes и info(). Ограничение: проверки dtype == object не работают, сравнивайте со str.

Резюме: в 3.0 строка — это str; старые проверки пересмотрите.
Что делает Copy-on-Write и почему chained assignment не работает?

CoW откладывает копирование до записи: .copy() независим, а колонка при правке отделяется от исходника. Цепочка df["a"][0] пишет во временную копию — pandas 3 печатает ChainedAssignmentError. Ограничение: предупреждение легко не заметить.

Резюме: запись — одной операцией через .loc.
