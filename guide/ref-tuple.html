tuple: опечатанный контейнер Неизменяемая запись, ключ словаря и возврат нескольких значений

tuple — это последовательность, которую нельзя изменить после создания. Здесь собрано, что из этого следует: всего два метода, зато полный набор операторов, срезов и распаковки, стабильный хеш для ключей — и границы, за которыми нужен список или dataclass.

⏱ 12 минут 🎯 уровень 1–2 🐍 Python 3.12 📚 глава 03

Типы справочника: вся карта · list · tuple · dict · set · Counter · defaultdict · deque

Самое главное
  • tuple — неизменяемая запись: элемент нельзя заменить, длину нельзя изменить. Зато он компактнее списка и hashable, если hashable все элементы.
  • Методов всего два — count и index. Всё остальное — операторы +, *, in, len, срезы и распаковка.
  • Годится в ключ dict и в set. Если данные будут меняться — берите list или dataclass, а не «кортеж, который придётся пересобирать».

01Что это и как устроено

Кортеж хранит упорядоченный набор объектов, зафиксированный при создании. Порядок — часть данных: (1, 2) и (2, 1) — разные кортежи, а доступ по индексу — O(1).

Внутри CPython — тот же массив указателей, что у списка, но без запаса на рост и без методов, меняющих длину. Размер известен при создании, поэтому кортеж компактнее (64 байта против 88 для трёх чисел) и быстрее создаётся. Главное следствие неизменяемости — hashable: если все элементы тоже hashable, у кортежа есть стабильный хеш, и его можно использовать как ключ словаря или элемент множества.

Неизменяемость неглубокая: ссылки заменить нельзя, а вложенный список менять можно — и тогда кортеж перестаёт быть hashable. Подробный разбор — в главе 03.

📦
Держите эту картинку в голове

Опечатанный контейнер. Груз загрузили один раз и запечатали: внутрь не заглянуть и груз не заменить. Зато контейнер можно проштамповать номерком — посчитать хеш — и отдать сразу нескольким получателям, не делая копий.

Отсюда четыре следствия: доступ по индексу за O(1), вставки и удаления нет вовсе, хеш стабилен, а роль в программе — запись, ключ и возврат нескольких значений. Метафору целиком разбирает глава 03.

Почему нет append и remove

Неизменяемость — это контракт, а не забытая функция: любая «изменяющая» операция над кортежем возвращает новый кортеж. Поэтому +, * и += здесь — создание, а не мутация.

05Разбор по группам

Все примеры страницы — в файле ref_tuple_lab.py: его можно запустить и менять строки.

count и index: два метода

ref_tuple_lab.pypython
orders = ("Anna", "Ivan", "Anna", "Olga")
print(orders.count("Anna"))
print(orders.index("Ivan"))
print(orders.index("Anna"))      # первое вхождение, а не второе
2 1 0

index всегда отдаёт первую позицию. Второе вхождение ищут с указанием старта: orders.index("Anna", 1). Если элемента нет, count вернёт 0, а index бросит ValueError.

Операторы +, *, in

ref_tuple_lab.pypython
a = (1, 2)
print(a + (3,))                  # новый tuple
print(a * 3)                     # повторение ссылок
print(len(a), 2 in a)            # in — перебор, O(n)
print(a == (1, 2), a < (1, 3))   # сравнение по элементам
(1, 2, 3) (1, 2, 1, 2, 1, 2) 2 True True True

+ и * создают новые кортежи. Сравнение идёт по элементам слева направо, как в словаре: первый различившийся элемент решает. Сравнивать кортежи с разными типами внутри (например, число и строку) нельзя — будет TypeError.

Срезы

ref_tuple_lab.pypython
point = (10, 20, 30, 40, 50)
print(point[0], point[-1])
print(point[1:4])                # срез tuple — тоже tuple
print(point[::2])
print(point[::-1])
10 50 (20, 30, 40) (10, 30, 50) (50, 40, 30, 20, 10)

Формула та же, что у списка: t[start:stop:step], где start включается, stop — нет. Отличие одно: результат — кортеж, а не список.

Распаковка

record = ("Anna", 1200, "2024-05-01")
name, amount, day = record
print(name, amount, day)

first, *middle, last = (1, 2, 3, 4, 5)

Число переменных должно совпадать с числом элементов — если не поставить звёздочку. *middle собирает всё лишнее в список, даже если исходник — кортеж. Та же звёздочка распаковывает кортеж в аргументы вызова.

Два одинаковых кортежа — один и тот же ключ: (1, 2) и (1, 2) сравниваются по значению. Но как только внутри появляется изменяемый объект, хеш посчитать нельзя — и кортеж перестаёт быть ключом.

namedtuple: запись с полями

ref_tuple_lab.pypython
from collections import namedtuple

Point = namedtuple("Point", "x y")
p = Point(10, 20)
print(p)
print(p.x, p.y)
print(p._replace(x=99))          # новый объект, исходный не меняется
print(p)
Point(x=10, y=20) 10 20 Point(x=99, y=20) Point(x=10, y=20)

namedtuple — подкласс tuple с именами полей: работает индексация, распаковка и хеширование, но появляется p.x и читаемый repr. _replace возвращает новый объект — как и положено неизменяемой записи.

dataclass(frozen=True): альтернатива

ref_tuple_lab.pypython
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True)
class Order:
    user: str
    amount: int

o = Order("Anna", 1200)
print(o)
print(o.user)
try:
    o.amount = 500               # поля заморожены
except FrozenInstanceError as e:
    print(type(e).__name__)
Order(user='Anna', amount=1200) Anna FrozenInstanceError

Когда у записи есть имена, типы и методы, dataclass(frozen=True) читается лучше безымянного кортежа — и остаётся hashable. Если заморозка не нужна, frozen=False даёт изменяемую запись, которой не страшны «пересборки» кортежа.

t += (x,): новый объект, а не мутация

ref_tuple_lab.pypython
def add_item(record, item):
    record += (item,)            # для tuple это новый объект и новая привязка
    return record

original = ("Anna",)
updated = add_item(original, "Olga")
print(original)
print(updated)
('Anna',) ('Anna', 'Olga')

Внутри функции += перепривязал локальное имя, но исходный кортеж вызывающего не изменился: кортеж неизменяем. Со списком тот же код менял бы данные снаружи — поэтому «добавить элемент» к записи означает «вернуть новую запись».

t * 2 с вложенным списком

ref_tuple_lab.pypython
row = ([1],)
doubled = row * 2
doubled[0].append(2)             # обе позиции смотрят на один список
print(doubled)
print(row)
([1, 2], [1, 2]) ([1, 2],)

Умножение повторяет ссылки, а не создаёт новые объекты. Внутри обеих позиций — один и тот же список, поэтому он изменился в двух местах сразу. Кортеж защищает только саму структуру, но не содержимое вложенных изменяемых объектов.

06Три сценария из практики

Запись заказа и распаковка

ref_tuple_lab.pypython
order = ("Anna", 1200, "2024-05-01", "paid", "gift")
user, amount, day, *flags = order
print(user, amount, day)
print(flags)
Anna 1200 2024-05-01 ['paid', 'gift']

Строка из БД или ответ сервиса часто приходит кортежем фиксированной структуры. Распаковка даёт имена полям без словаря, а звёздочка забирает необязательный хвост. Если полей много и они повторяются в коде — пора в namedtuple.

Составной ключ: (пользователь, день)

ref_tuple_lab.pypython
orders = [
    ("Anna", "2024-05-01", 1200),
    ("Anna", "2024-05-01", 500),
    ("Olga", "2024-05-01", 1500),
    ("Ivan", "2024-05-02", 800),
]
totals = {}
for user, day, amount in orders:
    key = (user, day)            # составной ключ
    totals[key] = totals.get(key, 0) + amount

for key in sorted(totals):
    print(key, totals[key])
('Anna', '2024-05-01') 1700 ('Ivan', '2024-05-02') 800 ('Olga', '2024-05-01') 1500

Два поля вместо склейки строк вроде "Anna|2024-05-01": не нужен разделитель, который может встретиться в данных, и сортировка идёт по полям по очереди. В pandas это MultiIndex, в SQL — составной PRIMARY KEY или GROUP BY по двум колонкам.

Возврат нескольких значений

ref_tuple_lab.pypython
def order_stats(amounts):
    return min(amounts), max(amounts), sum(amounts)

low, high, total = order_stats([1200, 800, 1500])
print(low, high, total)

orders = [("Anna", 1200), ("Olga", 1500), ("Ivan", 800)]
first, *other = orders
print(first)
print(other)
800 1500 3500 ('Anna', 1200) [('Olga', 1500), ('Ivan', 800)]

return a, b, c — это возврат одного кортежа. Поэтому функция «верни статистику» не требует словаря, а вызывающий код читается как присваивание. Список заказов при этом распаковывается звёздочкой: первый элемент отдельно, остальные — списком.

07Пять ошибок, на которых спотыкаются

Путать (1) и (1,)

(1) — это число в скобках, а не кортеж: тип int, и распаковка не сработает. Кортеж из одного элемента всегда с запятой.

Один элемент — (1,); пустой — (); проверка — type(x).__name__.
tuple с изменяемым элементом в ключах

{("anna", ["IT"]): 1200} падает с TypeError: unhashable type: 'list': хеш кортежа считается по элементам, а у списка хеша нет.

Внутри ключа — только hashable: строки, числа, tuple, frozenset. Для изменяемых полей — сериализация в строку или dataclass.
tuple для данных, которые будут меняться

Каждое «изменение» превращается в пересборку: t = t[:i] + (x,) + t[i+1:] — O(n) и новый объект. Код становится длиннее, а выигрыша нет.

Если содержимое меняется — list; если меняется запись с полями — dataclass (frozen или обычный).
Ждать от t += (x,) мутации

У кортежа += создаёт новый объект и перепривязывает имя. Внутри функции исходный кортеж вызывающего не изменится — в отличие от списка.

Возвращайте результат: return record + (item,), и присваивайте его вызывающему коду.
t * 2 с вложенным списком

Повторение копирует ссылки: ([1],) * 2 даёт две позиции, указывающие на один список. Изменили одну — изменились обе.

Не кладите изменяемые объекты в tuple; для независимых копий — сборка comprehension'ом или copy.deepcopy.

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем tuple отличается от list, если не считать скобок?

Тезис: list изменяем, tuple — нет.

Механика: кортеж выделяется ровно под свои элементы и не умеет менять длину; из неизменяемости растут компактность, скорость создания и hashable. Список держит запас на рост и умеет вставки-удаления, но ключом быть не может.

Ограничение: неизменяемость неглубокая — вложенный список внутри кортежа менять можно, и тогда кортеж теряет хеш.

Резюме: разница в изменяемости, а не в синтаксисе.
Почему tuple можно положить в ключ dict, а list — нет?

Ключ обязан быть hashable: нужен стабильный хеш, который не поедет после вставки. У кортежа хеш вычисляется по элементам и не меняется, пока не меняются элементы. Список можно изменить после создания, поэтому хеша у него нет.

Ограничение: хеш кортежа считается по элементам — значит, все они тоже должны быть hashable.

Резюме: hashable = неизменяемый по всему дереву.
Что вернут count и index, если элемента несколько или его нет?

count(x) считает все вхождения и возвращает 0, если элемента нет. index(x) возвращает позицию первого вхождения, а если элемента нет — бросает ValueError. У index есть необязательные start и stop, чтобы искать не с начала.

Резюме: count — «сколько», index — «где первый».
Зачем namedtuple и dataclass, если есть обычный tuple?

namedtuple даёт те же гарантии неизменяемости, но с именами полей: order.user вместо order[0], читаемый repr и метод _replace. dataclass(frozen=True) добавляет типы, методы и возможность развития класса, оставаясь hashable.

Ограничение: оба чуть тяжелее голого кортежа; для «просто двух чисел подряд» это лишняя церемония.

Резюме: tuple — минимум, namedtuple — имена, dataclass — поведение.
Как распаковать кортеж, если элементов больше, чем переменных?

Звёздочкой: first, *rest = t или first, *middle, last = t. Переменная со звёздочкой получает список, даже если исходник — кортеж; внутри одной распаковки звёздочка может быть только одна.

Резюме: без звёздочки число переменных обязано совпадать.

01 Уникальные пары

Дан список пар «пользователь — отдел». Уберите повторы, сохранив порядок первого появления.

условиеpython
pairs = [("Anna", "IT"), ("Ivan", "Sales"), ("Anna", "IT"), ("Olga", "IT")]
# ожидается: [('Anna', 'IT'), ('Ivan', 'Sales'), ('Olga', 'IT')]
Показать решение и разбор
решениеpython
pairs = [("Anna", "IT"), ("Ivan", "Sales"), ("Anna", "IT"), ("Olga", "IT")]
unique = list(dict.fromkeys(pairs))
print(unique)
[('Anna', 'IT'), ('Ivan', 'Sales'), ('Olga', 'IT')]

Что важно. Кортеж — hashable ключ, поэтому dict.fromkeys работает с парами как со значениями. Словарь помнит порядок вставки, а повтор ключа ничего не добавляет. С set(pairs) было бы короче, но порядок потерялся бы.

02 namedtuple из строки

Строка из БД пришла кортежем. Соберите из неё запись с полями user и amount.

условиеpython
row = ("Anna", 1200)
# ожидается: Order(user='Anna', amount=1200)
Показать решение и разбор
решениеpython
from collections import namedtuple

Order = namedtuple("Order", "user amount")
row = ("Anna", 1200)
order = Order(*row)
print(order)
print(order._asdict())
Order(user='Anna', amount=1200) {'user': 'Anna', 'amount': 1200}

Что важно. Звёздочка распаковывает строку в аргументы конструктора; порядок полей в Order должен совпадать с порядком в строке. _asdict() возвращает обычный dict — удобно для JSON и логов.

df = pd.DataFrame({"user": ["Anna", "Olga"], "amount": [1200, 1500]})

-- сравнение «записи» целиком, как t1 < t2
WHERE (city, age) > ('Москва', 30)

-- группировка по tuple-ключу
GROUP BY user_id, order_date

Строка таблицы — тоже фиксированная запись, которую идентифицирует ключ, а не позиция. Составной PRIMARY KEY и GROUP BY по двум колонкам — прямой родственник кортежа-ключа. Сравнение (city, age) > (...) работает как лексикографическое сравнение tuple.
