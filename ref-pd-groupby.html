groupby: разложить — посчитать — собрать size и count, agg и transform, доли — что вызвать и какой формы ждать

groupby — конвейер из трёх шагов: строки раскладываются по ключу, в каждой группе считается агрегат, результаты собираются в таблицу. Здесь — все операции, форма результата и пять ошибок, которые ломают отчёт тихо.

Самое главное
  • groupby — ленивый объект: считает следующая операция. size() — строки группы, count() — непустые значения колонки; на NaN они расходятся.
  • agg схлопывает таблицу до строки на группу, transform возвращает результат длины исходника, а filter — это HAVING.
  • NaN в ключе по умолчанию выпадает (dropna=True), группы сортируются по ключу, а не по агрегату. Топ — отдельный sort_values.

01Что это и как устроено

groupby реализует схему split-apply-combine: разложить строки по группам, посчитать в каждой группе, собрать ответ. Результат — новая таблица, в которой одна строка соответствует одной группе.

Сам вызов groupby("user") ничего не считает: он возвращает ленивый объект-описание. Вычисление запускает следующая операция — size(), agg(), transform(), filter(). Пока агрегат не вызван, проблемы в данных не видны: пропавшие NaN-ключи обнаружатся только в результате.

Держите эту картинку в голове

Разложить — посчитать — собрать. Строки раскладываются по лоткам с ярлыками, в каждом лотке считается своё число, лотки собираются в новую таблицу: одна строка на группу.

Это тот же блокнот, что totals[user] += amount из главы 02, только сразу для всех групп и с готовой таблицей на выходе. Подробный разбор — в главе 15.

groupby не заменяет фильтрацию: сначала отбирают строки маской, потом группируют. Фильтр групп — это filter, и он дороже обычной маски.

03Как подготовить данные

Группировка любит «длинную» таблицу: одна строка — один факт (заказ, клик, платёж), а ключ — обычная колонка. Отдельный индекс для ключа не нужен: groupby принимает имя колонки и сам разложит по ней строки.

Проверьте три вещи до вызова агрегата: в ключе нет NaN (иначе строки молча выпадут), ключ одного типа (смесь int и строк даст разные группы), имена колонок уникальны — иначе агрегат по имени выберет не ту колонку.

ref_pd_groupby_lab.pypython
orders = pd.DataFrame({
    "order_id": [1, 2, 3, 4, 5, 6],
    "user": ["Anna", "Ivan", "Anna", "Olga", "Ivan", "Ivan"],
    "city": ["Москва", "Казань", "Москва", "Казань", "Москва", "Казань"],
    "amount": [1200, 800, 500, 2100, 300, 400],
    "discount": [100.0, None, 50.0, None, 25.0, None],
})
print(orders)
print(orders.dtypes)

05Разбор по группам

Все примеры страницы собраны в файле ref_pd_groupby_lab.py — его можно запустить и менять строки.

Объект и size

g = orders.groupby("user")

DataFrameGroupBy user Anna 2 Ivan 3 Olga 1 dtype: int64

DataFrameGroupBy — только описание: «таблица, разложенная по user». Результат появляется после size(). Порядок групп — по ключу, потому что sort=True по умолчанию.

Несколько ключей

ref_pd_groupby_lab.pypython
print(orders.groupby(["city", "user"])["amount"].sum())
city user Казань Ivan 1200 Olga 2100 Москва Anna 1700 Ivan 300 Name: amount, dtype: int64

Список ключей даёт MultiIndex: первый уровень — city, второй — user. Уровни снимаются reset_index(), а срез по городу — .loc["Москва"].

Несколько агрегатов сразу

ref_pd_groupby_lab.pypython
print(orders.groupby("user")["amount"].agg(["sum", "mean", "median", "min", "max"]))
sum mean median min max user Anna 1700 850.0 850.0 500 1200 Ivan 1500 500.0 400.0 300 800 Olga 2100 2100.0 2100.0 2100 2100

agg со списком функций возвращает таблицу: строки — группы, столбцы — агрегаты. min и max сохраняют тип колонки, а mean и median — всегда float.

size против count

ref_pd_groupby_lab.pypython
print(orders.groupby("user").size())
print(orders.groupby("user")["discount"].count())
user Anna 2 Ivan 3 Olga 1 dtype: int64 user Anna 2 Ivan 1 Olga 0 Name: discount, dtype: int64
size — строки, count — заполненные ячейки

У Ivan три заказа, но известна только одна скидка: size → 3, count → 1. Вопрос «сколько заказов» — это size, «сколько известных значений» — count.

Именованная агрегация по разным колонкам

ref_pd_groupby_lab.pypython
print(orders.groupby("user").agg(total=("amount", "sum"), orders=("order_id", "count")))
total orders user Anna 1700 2 Ivan 1500 3 Olga 2100 1

В именованной агрегации каждая колонка результата задаётся явно: имя, колонка, функция. Так total считается по amount, а orders — по order_id, и результат не зависит от порядка колонок в таблице.

as_index=False и сортировка

ref_pd_groupby_lab.pypython
print(orders.groupby("user", as_index=False)["amount"].sum())
print(orders.groupby("user")["amount"].sum().sort_values(ascending=False))
user amount 0 Anna 1700 1 Ivan 1500 2 Olga 2100 user Olga 2100 Anna 1700 Ivan 1500 Name: amount, dtype: int64

as_index=False возвращает обычную таблицу: ключ — колонка, а не индекс. Такой результат проще фильтровать и соединять.

Вторая строка — про порядок: groupby сортирует группы по ключу, а не по величине агрегата. Топ — это отдельный sort_values(ascending=False).

transform против agg

ref_pd_groupby_lab.pypython
print(orders.groupby("user")["amount"].agg("mean").shape)
print(orders.groupby("user")["amount"].transform("mean").shape)
avg = orders.groupby("user")["amount"].transform("mean")
print(orders.assign(user_avg=avg))
(3,) (6,) order_id user city amount discount user_avg 0 1 Anna Москва 1200 100.0 850.0 1 2 Ivan Казань 800 NaN 500.0 2 3 Anna Москва 500 50.0 850.0 3 4 Olga Казань 2100 NaN 2100.0 4 5 Ivan Москва 300 25.0 500.0 5 6 Ivan Казань 400 NaN 500.0

Форма результата — главное различие: agg схлопывает шесть строк в три, transform возвращает шесть значений — агрегат повторён в каждой строке. Поэтому transform сразу становится колонкой, а agg пришлось бы присоединять через merge.

filter: HAVING по группам

ref_pd_groupby_lab.pypython
print(orders.groupby("user").filter(lambda group: len(group) > 1))
order_id user city amount discount 0 1 Anna Москва 1200 100.0 1 2 Ivan Казань 800 NaN 2 3 Anna Москва 500 50.0 4 5 Ivan Москва 300 25.0 5 6 Ivan Казань 400 NaN

filter отдаёт группе функцию, ждёт bool и оставляет строки прошедших групп. У Olga одна строка — вся группа отброшена; индексы исходных строк сохраняются, поэтому таблицу потом легко сравнить с оригиналом.

NaN в ключе: dropna

ref_pd_groupby_lab.pypython
clicks = pd.DataFrame({"user": ["Anna", None, "Ivan", "Anna"], "clicks": [3, 1, 5, 2]})
print(clicks)
print(clicks.groupby("user").size())
print(clicks.groupby("user", dropna=False).size())
user clicks 0 Anna 3 1 NaN 1 2 Ivan 5 3 Anna 2 user Anna 2 Ivan 1 dtype: int64 user Anna 2 Ivan 1 NaN 1 dtype: int64

По умолчанию groupby выбрасывает строки с NaN в ключе (dropna=True): во втором выводе два клика у Anna и один у Ivan, а строка с пропуском исчезла. dropna=False делает NaN отдельной группой — это единственный способ увидеть, сколько таких строк.

Доли и value_counts

ref_pd_groupby_lab.pypython
share = orders.groupby("user")["amount"].sum() / orders["amount"].sum()
print(share.round(3))
print(orders["user"].value_counts())
print(orders.groupby("user").size())
user Anna 0.321 Ivan 0.283 Olga 0.396 Name: amount, dtype: float64 user Ivan 3 Anna 2 Olga 1 Name: count, dtype: int64 user Anna 2 Ivan 3 Olga 1 dtype: int64

value_counts — короткий путь для одной колонки: сортирует по частоте (Ivan 3, Anna 2, Olga 1). groupby().size() сортирует по ключу и умеет несколько ключей и агрегаты по другим колонкам. Доля — это сумма группы, делённая на общий итог: g["amount"].sum() / df["amount"].sum().

report = (

Самый частый отчёт: сгруппировать, агрегировать, отсортировать. as_index=False делает результат готовым к merge, выгрузке в CSV и дальнейшим расчётам без reset_index().

Средний чек

ref_pd_groupby_lab.pypython
print(orders.groupby("user")["amount"].mean().round(2))
user Anna 850.0 Ivan 500.0 Olga 2100.0 Name: amount, dtype: float64

Средний чек — это mean по amount. round(2) здесь только для вывода: округлять промежуточные агрегаты до расчёта долей не стоит.

Доля каждого в общей сумме

ref_pd_groupby_lab.pypython
total = orders["amount"].sum()
shares = (orders.groupby("user")["amount"].sum() / total * 100).round(1)
print(shares)
user Anna 32.1 Ivan 28.3 Olga 39.6 Name: amount, dtype: float64

Доля — сумма группы, делённая на общий итог. Два разных вызова sum — по группам и по всей колонке — легко перепутать; общий итог считается без groupby.

07Пять ошибок, на которых спотыкаются

count вместо size на пропусках

count() считает заполненные ячейки: у Ivan три заказа, но скидка известна одна, поэтому count → 1, а не 3. Отчёт «сколько заказов» тихо занижается на все NaN.

Заказы — size() или count по колонке без пропусков; заполненные значения — count.
transform вместо agg — и наоборот

agg уменьшает таблицу до строки на группу, transform возвращает столько же строк. Присвоить agg-результат колонкой нельзя: длины не совпадут, а pandas выровняет по индексу и насыплет NaN.

Нужна колонка в исходной таблице — transform. Нужна сводка — agg.
NaN-ключ выпал из отчёта

По умолчанию dropna=True: строки с NaN в ключе не попадают ни в одну группу и не видны в результате. Сумма по группам при этом не сходится с общей суммой колонки.

dropna=False, если пропуск — отдельная группа; иначе fillna до группировки.
Сначала колонка, потом groupby

orders["amount"].groupby("user") падает с KeyError: 'user': в Series уже нет колонки-ключа. Группировать нужно таблицу, а колонку выбирать после.

orders.groupby("user")["amount"] — сначала groupby по таблице, потом выбор колонки.
Забыли as_index=False — получили индекс

Результат с индексом-группой не имеет колонки user: merge(..., on="user") и обращение result["user"] не работают. Индекс виден в выводе, но код о нём не знает.

as_index=False при группировке или reset_index() после.

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем size отличается от count?

size() считает строки группы целиком, включая пропуски. count() — непустые значения конкретной колонки. Если в колонке есть NaN, числа расходятся.

Резюме: size — строки, count — заполненные ячейки.
Чем agg отличается от transform и когда что брать?

agg схлопывает группу в одну строку — (3,) на нашем примере. transform возвращает результат длины исходной таблицы — (6,), поэтому его можно присвоить колонкой. Это разница между GROUP BY и оконной функцией.

Резюме: сводка — agg, колонка в исходнике — transform.
Как посчитать несколько агрегатов и назвать колонки?

Списком: agg(["count", "sum", "mean"]) — колонки получат имена функций. Именованно: agg(total=("amount", "sum"), orders=("order_id", "count")) — имя, колонка и функция задаются явно, можно брать разные колонки.

Резюме: список для быстрого взгляда, именованные пары — для отчёта.
Как сделать HAVING в pandas?

groupby(...).filter(lambda g: условие): функция получает группу-DataFrame и возвращает bool. Обычная маска до группировки — это WHERE, фильтр групп — HAVING.

Резюме: WHERE — до groupby, HAVING — внутри filter.
Что происходит с NaN в ключе и как посчитать долю?

По умолчанию строка с NaN-ключом выпадает. dropna=False оставляет её отдельной группой. Доля — сумма группы, делённая на общий итог: g["amount"].sum() / df["amount"].sum().

Резюме: проверьте ключ до группировки; доля — два разных sum.

01 Выручка, заказы и средний чек

По таблице orders постройте по пользователю сумму, число заказов и средний чек. Отсортируйте по сумме.

Показать решение и разбор
решениеpython
result = (
    orders.groupby("user", as_index=False)
    .agg(total=("amount", "sum"),
         orders=("order_id", "count"),
         avg=("amount", "mean"))
    .sort_values("total", ascending=False)
)
print(result)
user total orders avg 2 Olga 2100 1 2100.0 0 Anna 1700 2 850.0 1 Ivan 1500 3 500.0

Что важно. Три агрегата — три пары «имя, колонка, функция»; as_index=False оставляет user колонкой, а sort_values ставит группы по величине суммы.

02 Доля заказа в сумме пользователя

Добавьте колонку share_in_user — какую часть суммы пользователя составляет каждый заказ. Число строк не должно измениться.

Показать решение и разбор
решениеpython
user_total = orders.groupby("user")["amount"].transform("sum")
orders["share_in_user"] = (orders["amount"] / user_total).round(3)
print(orders[["order_id", "user", "amount", "share_in_user"]])
order_id user amount share_in_user 0 1 Anna 1200 0.706 1 2 Ivan 800 0.533 2 3 Anna 500 0.294 3 4 Olga 2100 1.000 4 5 Ivan 300 0.200 5 6 Ivan 400 0.267

Что важно. transform("sum") даёт NaN-free колонку той же длины, поэтому деление идёт построчно. agg здесь не подошёл бы: он вернул бы одну строку на группу.

09Мостик: SQL GROUP BY и defaultdict

SQL: GROUP BY и HAVING

мост в SQLsql
-- groupby("user")["amount"].sum()
SELECT user, SUM(amount) AS total
FROM orders
GROUP BY user
ORDER BY total DESC;

-- groupby("user").filter(lambda g: len(g) > 1) → HAVING
SELECT user, COUNT(*) AS orders
FROM orders
GROUP BY user
HAVING COUNT(*) > 1;

groupby — это GROUP BY, agg — агрегатные функции, filter — HAVING. transform схож с оконной функцией SUM(...) OVER (PARTITION BY ...). Синтаксис SQL разобран в главе 21.

Python: defaultdict

ref_pd_groupby_lab.pypython
totals = defaultdict(int)
for user, amount in zip(orders["user"], orders["amount"]):
    totals[user] += amount
print(dict(totals))
print(orders.groupby("user")["amount"].sum().to_dict())
{'Anna': 1700, 'Ivan': 1500, 'Olga': 2100} {'Anna': 1700, 'Ivan': 1500, 'Olga': 2100}

Ручной аккумулятор из главы 02 даёт тот же словарь — и это лучший способ проверить, что вы понимаете groupby. Разница в масштабе: цикл по строкам в Python медленный, а groupby делает то же векторно.
