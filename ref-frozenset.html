frozenset — это set, который нельзя изменить: те же операции, но с hash. Здесь полный список того, что можно, что нельзя и какого типа получается результат.

⏱ 10 минут 🎯 уровень 1–2 🐍 Python 3.12 📚 глава 04

Типы справочника: вся карта · str · list · tuple · dict · set · frozenset · Counter · defaultdict · deque

Самое главное
  • frozenset — неизменяемый set: те же операции, но нет методов изменения и есть hash. Поэтому он годится в ключ словаря и элемент другого множества.
  • Операции стоят как у set; hash(fs) — O(n) при первом вычислении. Равенство и хеш не зависят от порядка элементов.
  • Нужно менять набор — set; нужен порядок — list; нужен неизменяемый набор-идентификатор — frozenset.

01Что это и как устроено

frozenset — «замороженное» множество: та же хеш-таблица, что у set, но после создания её нельзя изменить. Повторы схлопываются, порядка нет, проверка входа — O(1) в среднем.

Отличие одно, но решающее: у frozenset есть hash. Он считается по элементам, порядок на него не влияет, а объект неизменяем — значит, хеш не «поедет». Отсюда два применения: ключ словаря и элемент другого множества. set так не умеет: он изменяем, поэтому нехешируем.

Хеш-таблица, коллизии и пробирование — в главе 02; фейс-контроль и четыре операции — в главе 04.

🪪
Держите эту картинку в голове

Заламинированный список. set — список гостей у фейс-контроля. frozenset — тот же список, но заламинированный: его можно читать, сравнивать с другими и складывать в картотеку, а дописать фамилию уже нельзя.

Зато заламинированный список можно повесить как бейдж — положить в ключ словаря или в другой список гостей. Изменить его можно только одним способом — напечатать новый; старый останется прежним.

frozenset(iterable) принимает любой итерируемый объект: список, строку, range, другое множество, ключи словаря. Повторы схлопываются, порядок теряется. Пустой набор — только frozenset().

Литерала нет

Запись {1, 2} — это set, а не frozenset: неизменяемый набор получается только вызовом frozenset(...). При этом {} — пустой dict, а не набор.

Чего у frozenset нет

Методов изменения не существует: add, remove, discard, pop, clear, update и все *_update. Обращение к ним — AttributeError, а не «тихая» попытка изменить.

05Разбор по группам

Все примеры страницы — в файле ref_frozenset_lab.py. Множества строк печатаются через sorted: порядок frozenset для строк зависит от хеша и меняется между запусками.

Неизменяемость: нет методов, изменение — новый объект

ref_frozenset_lab.pypython
fs = frozenset({1, 2})
modifiers = [
    "add", "remove", "discard", "pop", "clear", "update",
    "intersection_update", "difference_update", "symmetric_difference_update",
]
print([name for name in modifiers if hasattr(fs, name)])
try:
    fs.add(3)                    # у set метод есть, у frozenset — нет
except AttributeError as e:
    print(type(e).__name__, e)
print(sorted(fs))

alias = fs
fs |= {3}                        # это переприсваивание, а не мутация
print(sorted(alias), sorted(fs))
print(alias is fs, alias == fs)
[] AttributeError 'frozenset' object has no attribute 'add' [1, 2] [1, 2] [1, 2, 3] False False

hasattr возвращает пустой список: методов изменения у типа нет — это не «запрет во время выполнения», а отсутствие операции. Код со страницы set упадёт на первой строке. А fs |= {3} выглядит как изменение на месте, но это fs = fs | {3}: создаётся новый набор, имя указывает на него, старый объект и все алиасы остаются прежними.

В этом смысл: frozenset безопасно передавать в функции — никто не изменит его «на месте». Обратная сторона: код, ждущий, что алиас увидит правку, тихо получит старое значение. Нужна мутация — это set.

Hashable: ключ, элемент, вложение

hash(fs) считается по элементам и не зависит от порядка: {"read", "write"} и {"write", "read"} дают один и тот же хеш. Поэтому frozenset годится в ключ словаря и элемент множества, а внутрь можно вложить frozenset — обычный set нехешируем.

Порядок не влияет ни на равенство, ни на хеш: frozenset({1, 2}) == frozenset({2, 1}), и frozenset({1, 2}) == {2, 1} — тоже True: равенство сравнивает элементы, а не тип. Но хешируется только frozenset — set остаётся нехешируемым и в ключ не годится.

В CPython хеш запоминается в объекте: O(n) платится только при первом вычислении. Это деталь реализации, а не обещание документации.

Операции и тип результата

['dbt', 'pandas', 'python', 'sql'] ['python', 'sql'] ['pandas'] ['dbt', 'pandas'] ['airflow', 'pandas', 'python', 'sql'] ['sql'] ['pandas', 'python'] ['go', 'pandas', 'sql'] frozenset [1, 2, 3] set [1, 2, 3] frozenset set frozenset set frozenset set frozenset True frozenset

Четыре операции отвечают на четыре вопроса: «хоть где-то», «и там, и там», «только здесь», «ровно в одном». Методы union, intersection, difference, symmetric_difference принимают любой итерируемый объект и всегда возвращают новый frozenset; исходные наборы не меняются. Операторы же требуют set-подобного операнда с обеих сторон: fs | [1] бросит TypeError.

Ключевая деталь: в CPython тип результата смешанной операции определяет левый операнд. fs | ms даёт frozenset, ms | fs — set; то же для &, - и ^. Методы всегда возвращают frozenset, потому что вызываются у него. Если тип результата важен (например, он пойдёт в ключ словаря), не полагайтесь на смешанный оператор: оберните явно frozenset(fs | ms) или используйте fs.union(ms).

fs.copy() is fs → True в CPython 3.12: копия не создаётся, потому что объект неизменяем. Это оптимизация, а не контракт.

06Три сценария из практики

Реестр ролей и кэш по набору прав

ref_frozenset_lab.pypython
role_by_perms = {
    frozenset({"read"}): "viewer",
    frozenset({"read", "write"}): "editor",
    frozenset({"read", "write", "delete"}): "admin",
}
raw_perms = ["write", "read", "write"]       # пришло из API, с дублем
key = frozenset(raw_perms)
print(key in role_by_perms, role_by_perms[key])

cache = {}

def role(perms):
    key = frozenset(perms)
    if key not in cache:
        cache[key] = role_by_perms.get(key, "viewer")
    return cache[key]

print(role({"read"}), role(["write", "read"]), role({"read"}))
print(len(cache))
True editor viewer editor viewer 2

Набор прав — естественный идентификатор роли, а frozenset — естественный ключ. Права из API приходят списком, с дублями и в любом порядке: frozenset(raw_perms) нормализует их за O(n), и запрос попадает в ту же запись. Кэш устроен так же: три вызова, но записей две — {"read"} и ["write", "read"] дают один ключ, третий вызов попадает в кэш.

Набор прав как ключ группировки

ref_frozenset_lab.pypython
users = {
    "Anna": {"read", "write"},
    "Olga": {"read"},
    "Ivan": {"read", "write", "delete"},
}
by_perms = {}
for user, perms in users.items():
    by_perms.setdefault(frozenset(perms), []).append(user)
for perms, people in sorted(by_perms.items(), key=lambda kv: sorted(kv[0])):
    print(sorted(perms), sorted(people))
['delete', 'read', 'write'] ['Ivan'] ['read'] ['Olga'] ['read', 'write'] ['Anna']

Обратная задача: не «какая роль у набора», а «кто с одинаковым набором». Здесь frozenset работает ключом словаря-группировки, как строка или число: setdefault и defaultdict(list) принимают его без оговорок. Группы напечатаны в порядке sorted(perms), а не в порядке словаря: repr frozenset из строк зависит от хеша и между запусками меняется.

Дедупликация комбинаций

ref_frozenset_lab.pypython
pairs = [
    frozenset({"Anna", "Olga"}),
    frozenset({"Olga", "Anna"}),      # тот же набор
    frozenset({"Ivan", "Anna"}),
    frozenset({"Ivan", "Anna"}),      # повтор
]
unique = set(pairs)
print(len(pairs), len(unique))

    print(sorted(pair))

Комбинация «кто с кем» — пара без порядка: (Anna, Olga) и (Olga, Anna) — одно и то же. Если хранить пары как frozenset, перевёрнутые варианты схлопнутся сами: set(pairs) оставит две уникальные пары из четырёх. Кортеж так не сработал бы — порядок пришлось бы нормализовать вручную.

07Пять ошибок, на которых спотыкаются

add и другие методы set

fs.add(3) падает с AttributeError: 'frozenset' object has no attribute 'add'. То же с remove, discard, pop, clear, update и *_update — методов изменения у типа нет.

Изменять только новым объектом: fs = fs | {3}, fs = fs - {1}. Нужна мутация — берите set.
Ждать мутации от |=

fs |= {3} не меняет набор, на который смотрят другие ссылки: создаётся новый объект и имя переприсваивается. Функция, передавшая fs дальше, продолжит видеть старый набор — и это не баг, а неизменяемость.

Не рассчитывайте на общий изменяемый объект: возвращайте новый набор из функции. Если изменения должны быть видны всем — set.
Нехешируемый элемент

frozenset([[1, 2]]) и frozenset([{1, 2}]) бросают TypeError: unhashable type: список и обычное множество внутрь не кладутся. Ошибка выстреливает при создании, а не при обращении.

Неизменяемые аналоги: кортеж вместо списка (frozenset({(1, 2)})), frozenset вместо set (frozenset({frozenset({1, 2})})).
JSON-сериализация

json.dumps({"perms": frozenset({"read"})}) падает с TypeError: Object of type frozenset is not JSON serializable: в JSON нет множеств.

На выход — sorted(fs) (список); на вход — frozenset(data["perms"]). Сортировка делает представление каноническим: одинаковые наборы дают одинаковый JSON.
Ставка на порядок в repr и итерации

print(fs) и list(fs) для строк зависят от хешей: frozenset({'read', 'write'}) и frozenset({'write', 'read'}) — один и тот же набор с разным текстом. Тест, сравнивающий строку с эталоном, будет падать через раз.

Для вывода — sorted(fs); для проверки — сравнение наборов: fs == frozenset({...}). На равенство и хеш порядок не влияет.

08Мини-проверка

Пять вопросов и две задачи. Сначала своя попытка — потом спойлер.

Чем frozenset отличается от set?

Только изменяемостью и связанной с ней хешируемостью: операции, отношения и цена общие; методов изменения у frozenset нет, зато есть hash — значит, его можно класть в ключ словаря и элемент множества.

Ограничение: hash(fs) — O(n) при первом вычислении, для миллиона элементов это заметно.

Резюме: frozenset = set, который нельзя изменить и можно захешировать.
Почему frozenset можно сделать ключом словаря, а set — нельзя?

Ключ обязан быть hashable: хеш должен оставаться стабильным, пока объект в таблице. set изменяем — хеш мог бы «поехать», поэтому hash(set()) бросает TypeError. frozenset неизменяем: его хеш считается по элементам и не меняется.

Резюме: неизменяемость — условие стабильного хеша.
Что вернут frozenset | set и set | frozenset?

В CPython тип результата определяет левый операнд: frozenset | set → frozenset, set | frozenset → set. То же для &, - и ^. А методы fs.union(ms) и fs.intersection(ms) всегда возвращают frozenset.

Резюме: слева frozenset — справа frozenset; надёжнее — метод.
Правда ли, что frozenset({1, 2}) == {2, 1}?

Да: равенство множеств сравнивает элементы, а не тип, и порядок не важен. При этом hash(frozenset({1, 2})) == hash(frozenset({2, 1})), но сам set это не делает хешируемым — в ключ его не положить.

Резюме: равенство — про элементы, hash — только про frozenset.
isinstance(fs, set) — что вернёт и как проверять тип правильно?

False: frozenset — не подкласс set, а соседний тип с общим набором операций. Точная проверка — isinstance(fs, frozenset); «любой set-подобный» — isinstance(x, (set, frozenset)) или collections.abc.Set (MutableSet для frozenset — False).

Резюме: frozenset и set — соседи, а не родственники.

01 Чего не хватает до роли

Есть требуемый набор прав и текущий набор пользователя. Найдите, каких прав не хватает, и покажите тип результата.

условиеpython
REQUIRED = frozenset({"read", "write", "delete"})
current = {"read", "write"}
# ожидается: frozenset 1 ['delete']
# и проверка, что разность набора с самим собой пуста
Показать решение и разбор
решениеpython
REQUIRED = frozenset({"read", "write", "delete"})
current = {"read", "write"}
missing = REQUIRED - current
print(type(missing).__name__, len(missing), sorted(missing))
print(REQUIRED - REQUIRED == frozenset())
frozenset 1 ['delete'] True

Что важно. REQUIRED — неизменяемая константа, её нельзя случайно испортить. Разность frozenset - set возвращает frozenset (левый операнд), а разность набора с собой — пустой frozenset, не set. Результат можно сразу использовать как ключ.

02 Фильтр по запрещённым тегам

Запрещённые теги — неизменяемая константа. Оставьте посты, у которых нет ни одного запрещённого тега.

условиеpython
BLOCKED = frozenset({"adult", "spam", "violence"})
posts = [
    ("post-1", {"python", "sql"}),
    ("post-2", {"python", "spam"}),
    ("post-3", {"pandas", "adult", "sql"}),
]
# ожидается: ['post-1']
Показать решение и разбор
решениеpython
BLOCKED = frozenset({"adult", "spam", "violence"})
posts = [
    ("post-1", {"python", "sql"}),
    ("post-2", {"python", "spam"}),
    ("post-3", {"pandas", "adult", "sql"}),
]
for post_id, tags in posts:
    print(post_id, BLOCKED.isdisjoint(tags))
allowed = [post_id for post_id, tags in posts if BLOCKED.isdisjoint(tags)]
print(allowed)
post-1 True post-2 False post-3 False ['post-1']

Что важно. isdisjoint проверяет «нет общих элементов» и принимает обычный set тегов. Константа BLOCKED заморожена: её нельзя дополнить по ошибке из кода обработки. Проверка линейна по меньшему набору (O(min(n, k))).

09Мостик: та же идея в pandas, SQL и API

pandas: набор как значение столбца

мост в pandaspython
import pandas as pd

df = pd.DataFrame({"user": ["Anna", "Olga", "Ivan"]})
df["perms"] = [
    frozenset({"read", "write"}),
    frozenset({"read"}),
    frozenset({"read", "write", "delete"}),
]
df["perms"].map(len)                                   # как len(fs) для каждой строки
df["perms"].isin([frozenset({"read"})])                # сравнение наборов как наборов
df[df["perms"].map(lambda p: "delete" in p)]           # как `x in fs`

В pandas набор можно хранить значением столбца, если он hashable, — ровно поэтому frozenset, а не set.

SQL: набор без порядка и дедупликация комбинаций

мост в SQLsql
-- проверка входа: как `x in fs`
SELECT * FROM users WHERE id IN (1, 2, 3);

-- уникальные комбинации: порядок внутри пары не важен — нормализуем и группируем
SELECT LEAST(user_a, user_b)    AS u1,
       GREATEST(user_a, user_b) AS u2,
       COUNT(*)                 AS times
FROM pairs
GROUP BY LEAST(user_a, user_b), GREATEST(user_a, user_b);

-- операции над наборами строк
SELECT user_id FROM a UNION     SELECT user_id FROM b;   -- объединение
SELECT user_id FROM a INTERSECT SELECT user_id FROM b;   -- пересечение
SELECT user_id FROM a EXCEPT    SELECT user_id FROM b;   -- разность

UNION неявно делает DISTINCT — строит множество и платит за это; UNION ALL дешевле, если дубли допустимы. Идею «порядок не важен» в SQL выражает нормализация (LEAST/ GREATEST, sorted перед сохранением) — тот же приём, что frozenset в Python.

API: ключ кэша и канонический JSON

мост в APIpython
# ключ кэша: набор прав из запроса, порядок и дубли не важны
key = frozenset(request["permissions"])
cache.setdefault(key, compute_role(key))

# в JSON — только список; сортировка делает вид каноническим
response = {"permissions": sorted(key)}

В API набор прав — это «множество без порядка», и frozenset переводит его в состояние, пригодное для ключа кэша. На границе сериализации набор становится списком — сортировка придаёт ему один и тот же вид, а при чтении ответа frozenset(data["permissions"]) возвращает набор.
